§1一切从一个问题开始 · "他" 应该关注什么

考虑这样一句话：

"小明 把 书 借给 小红 , 他 忘了 还"

"他"指的是谁？人类一眼知道是"小明"——因为"借给"说明借出方是主语。那么模型凭什么知道？

Attention 的朴素目标：对每个位置的 token，计算一组权重 w1, w2, ..., wn，告诉它"上下文每个词对我当前语义贡献多少"，然后按权重把上下文的信息加权汇总过来。

数学上就是：

新的 "他"_embedding = w₁·"小明" + w₂·"把" + w₃·"书" + ... + wₙ·"还"

问题只剩一个——w 怎么算？

§2第一步 · 用点积衡量"相似度"

最朴素想法：两个向量方向越接近，点积越大。如果"他"和"小明"的 embedding 点积大，就说明它俩语义相关。

# 设每个 token 的 embedding 是 d 维向量
x_他 = [0.2, 0.8, -0.1, ...]     (d=4)
x_小明 = [0.3, 0.7, -0.05, ...]
x_书   = [-0.1, 0.2, 0.9, ...]

score(他, 小明) = x_他 · x_小明    # 标量
score(他, 书)   = x_他 · x_书

# 如果前者更大，说明"他" 更像"小明"
但这里有一个 bug：x · x 永远最大（自己跟自己最像）。这就意味着每个 token 永远只关注自己，信息根本流不动。而且，"相似"和"该关注"不是一回事——"他"跟"小明"字面不像，但"他"该关注"小明"，这怎么办？

§3第二步 · 引入 Q K V 三组可学习的投影

解决办法：给每个 token 三个不同的"脸"。同一个 embedding x，分别投影成：

Q = x · WQ
Query 脸——"我要找什么"
K = x · WK
Key 脸——"我能被谁找到"（像个广告牌）
V = x · WV
Value 脸——"我被找到后贡献什么"

然后把分数公式改成：

score(i → j) = Qi · Kj     # 位置 i 的 Query 和位置 j 的 Key 点积

为什么这个设计 genius

  • Q 和 K 是不同投影——即使 i=j，Qi·Ki 不必最大。模型能学会"我该关注的不是自己"
  • W_Q / W_K / W_V 是可学习参数——模型可以自己学出"我该用哪种相似度"
  • Value 独立——"找到你"和"用你"可以不是同一组信息。比如"小明"的 Key 可能编码"这是人名"，Value 可能编码"小明是个学生、喜欢读书"这种传递出去的内容

§4第三步 · 为什么要 softmax · 不能直接用原始 score 吗

原始点积 score 有三个缺点：

  1. 可正可负——没法当权重
  2. 尺度不固定——不同层 score 数量级差很远
  3. 不归一化——加权和可能爆炸

softmax 把一串数变成"概率分布"：

softmax(s)i = exp(si) / Σj exp(sj)

# 三个关键性质
1. 每个数 > 0              # 适合当权重
2. 加起来 = 1               # 天然归一化
3. 放大差异                 # score 差 1 → 概率差 e≈2.7 倍
性质 3 特别重要：softmax 让"最相关的那几个 token 获得绝大部分注意力"，其他的权重接近 0。这正是"关注"这个词的含义——注意力稀疏而集中，而不是均匀分散。

到这一步，公式长这样：

Attention(Q, K, V) = softmax(Q · Kᵀ) · V

还差最后一个神秘系数 /√d。

§5第四步 · /√d 是在治什么病

假设 Q、K 都是 d 维、每个分量是独立的标准正态（均值 0，方差 1）：

score = Q · K = Σi=1..d Qi Ki

# 独立乘积的期望 = 0
# 独立乘积的方差 = 1
# d 项相加：方差 = d，标准差 = √d

E[score]   = 0
Var[score] = d
Std[score] = √d

d=128 时，score 的典型量级是 ±√128 ≈ ±11。走一把 softmax：

softmax([-11, 10, 11, -10]) ≈ [0, 0.27, 0.73, 0]
发现问题了吗？——softmax 变成了接近 one-hot，几乎只选一个 token。梯度只会流向"赢家"，其他 key 的梯度趋近于 0，训练直接梯度消失。这就是为什么必须除以 √d。 
score = (Q · K) / √d     # 除完后方差变回 1

除完之后 softmax 变得温和而可微，梯度也能合理地分散到所有 token——训练才能跑起来。

最终公式

Attention(Q, K, V) = softmax(Q · Kᵀ / √d) · V

这就是 2017 年那篇 Attention Is All You Need 的核心——但它不是凭空来的，是被四个工程问题依次逼出来的：
相似度 → 分离 Q/K/V → 归一化 → 尺度平稳。

§7为什么还要 "多头" · 一个 d 维不够用

到目前我们讲的是 single-head attention：一套 Q/K/V 投影，一次 softmax。但实际 Transformer 都是 multi-head attention (MHA)，原因：

  • 一个 softmax 只能分配一次"注意力"。但一个 token 可能同时有多个独立的关注对象："他" 既要关注"小明"（找指代），又要关注"忘了"（找动作关系）。一套 softmax 抢不过来
  • 解决办法：把 d 维切成 h 组，每组独立做 Q/K/V 投影 + attention。h 个"头"各关注各的，最后拼回来
# d_model = 4096, num_heads = 32, head_dim = 128
Q.shape = [N, 32, 128]    # 32 个头，每个头内做独立 attention
K.shape = [N, 32, 128]
V.shape = [N, 32, 128]

# 每个头独立 softmax 独立汇总
head_i = softmax(Q[:,i,:] · K[:,i,:].T / √128) · V[:,i,:]

# 最后拼接 32 个头 → (N, 32*128) = (N, 4096)
output = concat(head_0, ..., head_31) · W_O
下一章埋伏笔：32 个头都独立存 K/V → KV Cache 体积 = 2 · L · 32 · 128 · 2byte / token。模型越大、头越多，decode 时要搬的 KV 就越吓人。GQA (Grouped Query Attention) 就是在这里开刀省 KV——下一节讲。
