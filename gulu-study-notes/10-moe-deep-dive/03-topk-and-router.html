§0TopK 的三种输出格式

SGLang 的 TopK 模块根据不同的下游消费者，输出三种不同的数据结构：

StandardTopKOutput

最通用的格式，被大多数 Runner 使用：

@dataclass
class StandardTopKOutput:
    topk_weights: Tensor
    # [num_tokens, top_k]
    topk_ids: Tensor
    # [num_tokens, top_k]
    router_logits: Tensor
    # [num_tokens, num_experts]

用于 StandardDispatcher + 所有 Runner 后端

TritonKernelTopKOutput

专为 Triton kernel routing 优化：

@dataclass
class TritonKernelTopKOutput:
    topk_weights: Tensor
    topk_ids: Tensor
    sorted_token_ids: Tensor
    expert_ids: Tensor
    num_tokens_post_pad: Tensor

预排序，Triton kernel 直接消费无需再 dispatch

BypassedTopKOutput

CUDA Graph 场景，跳过动态 top-k：

@dataclass
class BypassedTopKOutput:
    topk_weights: Tensor
    topk_ids: Tensor
    # 预计算，不做实时路由
    # 用于 piecewise CUDA
    # graph replay

decode 阶段 CUDA Graph 需要固定形状

设计意图：三种输出格式体现了 SGLang 的"按需适配"哲学——同一个 TopK 逻辑，根据下游 Runner/Dispatcher 的需求， 输出最高效的中间表示，避免不必要的数据变换。

§1Fused Router Kernel

为什么要融合 Router？

传统实现中，路由分三步 kernel：

  1. gate_linear: x @ W_gate → router_logits（GEMM kernel）
  2. softmax: logits → probabilities（element-wise kernel）
  3. topk: 选出 top-k indices 和 weights（排序 kernel）

每一步都产生 HBM 读写。Fused Router 将三步合并为 一个 Triton kernel，中间结果全部在寄存器/SRAM 中完成。

核心 Triton Kernel 代码

# 来源: sglang/srt/layers/moe/topk.py → fused_moe_router_cudacore_kernel

@triton.jit
def fused_moe_router_cudacore_kernel(
    input_ptr,         # hidden_states [M, K]
    gate_ptr,          # W_gate [K, E]
    topk_weights_ptr,  # output: [M, top_k]
    topk_ids_ptr,      # output: [M, top_k]
    correction_bias_ptr,
    M, K, E, top_k,
    softcap,
    BLOCK_M: tl.constexpr,
    BLOCK_K: tl.constexpr,
    BLOCK_E: tl.constexpr,
):
    # ─── Step 1: 计算 router_logits = input @ gate ───
    pid_m = tl.program_id(0)
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_k = tl.arange(0, BLOCK_K)
    offs_e = tl.arange(0, BLOCK_E)

    # Accumulate dot product in registers
    logits = tl.zeros([BLOCK_M, BLOCK_E], dtype=tl.float32)
    for k_start in range(0, K, BLOCK_K):
        x = tl.load(input_ptr + offs_m[:, None] * K + (k_start + offs_k)[None, :])
        g = tl.load(gate_ptr + (k_start + offs_k)[:, None] * E + offs_e[None, :])
        logits += tl.dot(x, g)

    # ─── Step 2: Softcap (optional, 用于 Gemma 等模型) ───
    if softcap > 0:
        logits = softcap * tl.math.tanh(logits / softcap)

    # ─── Step 3: Correction bias (DeepSeek-V3) ───
    if correction_bias_ptr is not None:
        bias = tl.load(correction_bias_ptr + offs_e)
        logits += bias[None, :]

    # ─── Step 4: Softmax ───
    logits_max = tl.max(logits, axis=1)[:, None]
    logits = logits - logits_max
    exp_logits = tl.exp(logits)
    sum_exp = tl.sum(exp_logits, axis=1)[:, None]
    probs = exp_logits / sum_exp

    # ─── Step 5: Top-K selection (register-level) ───
    # Iteratively find top-k by masking used indices
    for i in range(top_k):
        max_val = tl.max(probs, axis=1)
        max_idx = tl.argmax(probs, axis=1)
        tl.store(topk_weights_ptr + offs_m * top_k + i, max_val)
        tl.store(topk_ids_ptr + offs_m * top_k + i, max_idx)
        # Mask selected expert
        mask = tl.arange(0, BLOCK_E)[None, :] == max_idx[:, None]
        probs = tl.where(mask, 0.0, probs)
性能收益：Fused Router 将 3 次 HBM 读写减少为 1 次（只读 input + gate，写 topk 结果）。 对于 256 expert 的 DeepSeek-V3，这可节省约 2× 的 router 延迟。

§2Grouped TopK for DeepSeek

问题：256 个 Expert 的负载均衡

DeepSeek-V3 有 256 个 routed expert，直接选 top-8 容易集中在少数 expert。 Grouped TopK 两阶段选择确保 diversity：

  1. 选组：将 256 expert 分为 num_expert_group=8 组（每组 32 expert），选出 topk_group=4 个组
  2. 组内选 expert：在选中的 4 个组内选 top-8（每组约 2 个）

实现代码

# 来源: flashinfer fused_topk_deepseek (被 SGLang 调用)

def grouped_topk(
    hidden_states: Tensor,       # [M, hidden]
    router_logits: Tensor,       # [M, num_experts=256]
    top_k: int = 8,
    renormalize: bool = True,
    num_expert_group: int = 8,   # 分 8 组
    topk_group: int = 4,         # 选 4 组
):
    scores = softmax(router_logits, dim=-1)  # [M, 256]

    # Step 1: 每组取 max score 作为组得分
    scores_grouped = scores.view(M, num_expert_group, -1)  # [M, 8, 32]
    group_scores = scores_grouped.max(dim=-1).values          # [M, 8]

    # Step 2: 选出 top-4 组
    _, top_groups = torch.topk(group_scores, k=topk_group)    # [M, 4]

    # Step 3: 屏蔽未选中组的 score
    group_mask = torch.zeros_like(group_scores).scatter_(1, top_groups, 1.0)
    expert_mask = group_mask.repeat_interleave(32, dim=1)      # [M, 256]
    scores = scores * expert_mask

    # Step 4: 在剩余中选 top-8
    topk_weights, topk_ids = torch.topk(scores, k=top_k)

    if renormalize:
        topk_weights = topk_weights / topk_weights.sum(dim=-1, keepdim=True)

    return topk_weights, topk_ids
注意：Grouped TopK 的分组方式是在训练时确定的，推理时必须与训练一致。 num_expert_group 和 topk_group 来自模型配置文件。

§3TopKConfig 参数详解

字段类型默认值说明
top_k int — 每个 token 选择的 expert 数量
use_grouped_topk bool False 是否启用分组选择（DeepSeek 风格）
topk_group int None 选中的组数（需配合 use_grouped_topk）
num_expert_group int None expert 分组总数
renormalize bool True 选中的权重是否重新归一化到 sum=1
scoring_func str "softmax" 打分函数："softmax" 或 "sigmoid"
routed_scaling_factor float 1.0 路由权重的缩放因子（DeepSeek-V3 使用）
correction_bias Tensor None 每个 expert 的偏置修正项，用于负载均衡
softcap float 0.0 logits 的 tanh softcap（Gemma 模型使用）
scoring_func 区别：
  • softmax：权重总和为 1，适合传统 MoE（Mixtral）
  • sigmoid：各 expert 独立评分，配合 routed_scaling_factor 缩放，适合 DeepSeek-V3 风格

§4源码关键路径

调用链

代码片段：SparseMoeBlock.forward

# 以 Qwen3MoeSparseMoeBlock 为例（简化）

class Qwen3MoeSparseMoeBlock(nn.Module):
    def forward(self, hidden_states: Tensor) -> Tensor:
        # Step 1: 计算 router logits
        router_logits = self.gate(hidden_states)  # nn.Linear(hidden, num_experts)

        # Step 2: TopK 路由选择
        topk_output = self.topk(hidden_states, router_logits)

        # Step 3: FusedMoE 计算
        final_hidden = self.fused_moe(
            hidden_states=hidden_states,
            topk_output=topk_output,
            w13=self.w13,
            w2=self.w2,
        )

        # Step 4: 加上 shared expert（如果有）
        if self.shared_expert is not None:
            shared_out = self.shared_expert(hidden_states)
            final_hidden = final_hidden + shared_out

        return final_hidden
Fused Router 的触发条件：当以下条件同时满足时启用 FusedRouterTopK：
  • 模型 expert 数 ≤ BLOCK_E（通常 256）
  • 未使用 grouped_topk（DeepSeek 用单独路径）
  • Triton 可用
否则回退到 StandardTopK (PyTorch 实现)。
