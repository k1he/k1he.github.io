PART 1PD 生产必看的核心指标

PD 把一次请求分成了 "Router 决策 + 两端排队 + KV transfer + D decode" 多段，排查性能必须拆到每段。

PART 2失败路径：每个点都要清理到底

PD 里一个请求跨越多个进程和 buffer，任意一个环节失败都要完整清理：KV pool、tree cache 前缀锁、metadata buffer slot、sender/receiver 对象、transfer_infos 表项、Router 的活跃请求计数。漏清一个都会让后续请求命中"幽灵资源"。

典型清理链路

// disaggregation/prefill.py (P 侧失败清理)
def release_kv_cache(req, tree_cache, insert=True):
    tree_cache.cache_finished_req(req, insert=insert)   # 解锁前缀
    req.release_resource()                                # 释放 req_pool_idx + KV slot

def _cleanup_failed_req(req):
    release_kv_cache(req, tree_cache, insert=False)   # 失败时不插 tree（前缀可能坏）
    self.req_to_metadata_buffer_idx_allocator.free(req.metadata_buffer_index)
    self.kv_manager.remove_transfer_infos(req.bootstrap_room)
    self.metrics_collector.increment_transfer_failed_reqs()

PART 6PD 故障排查 checklist

  1. Router 是否看到两边 worker：curl /workers，检查 prefill / decode 数量
  2. BootstrapServer 是否 ready：curl http://p:bootstrap_port/health
  3. P rank 数量对不对：curl /route?dp=-1&cp=-1&tp=-1&pp=-1，应该等于 dp·cp·tp·pp
  4. D 到 P 的 ZMQ 能连通吗：从 D 机 nc -z P_host P_bootstrap_port
  5. 队列长度趋势：P 的 BootstrapQueue/WaitingQueue/InflightQueue，D 的 PreallocQueue/TransferQueue
  6. KV transfer 速率：kv_transfer_speed_gb_s 是否合理（IB 10~30，NVLink 40+）
  7. bootstrap_failed / transfer_failed 计数：0 是健康，>0 必须进日志排查
  8. metrics buffer 使用率：avail_size 一直减不回来 = 泄露，立刻 kill 重启排查
  9. cache_aware 的命中率：是不是 cache miss 高导致 P 选错
  10. 失败请求是否干净：对比 req_pool available_size 在失败前后差值

PART 7本章要点

问题答案
排查 PD 性能的第一步？把 TTFT 拆到每段（Router / bootstrap / waiting / forward / transfer / commit）
bootstrap_failed vs transfer_failed？前者是握手没成功（ZMQ/拓扑问题）；后者是握手 OK 但 RDMA 没成功
D 的 KV pool 满怎么办？调大 max_total_tokens、SGLANG_DISAGGREGATION_NUM_PRE_ALLOCATE_REQS；或在 Router 侧限流
怎么安全下线一台 P？Router DELETE /workers → 停接新请求 → 等 in-flight 清空 → kill 进程
EPD 和 PD 关系？EPD 是 PD 的超集：在 P 前多加一段 Encoder worker
