这一章按"原理 → 源码 → 请求流转 → 交互演示"的结构重写。每一页先讲清楚这个模块的核心原理和数据结构，再拆源码，最后用一个可播放/可点击的 demo 展示"一个请求到这里会被怎么处理"。

学习路径推荐：

  1. 先看 01 why-pd 理解动机，用 Roofline demo 亲眼看 P/D 为什么不能同池

  3. 然后按 03 → 04 → 05 → 06 顺序钻每个模块
  4. 用 07 的 metrics dashboard 练习故障诊断
  5. 最后看 08，拆解 Tokenizer CPU 热路径以及 PD/非 PD 的放置差异

01 · 为什么必须 PD 分离

P/D 的计算特性差异（compute vs memory bound）、同池导致的 ITL 抖动、Chunked Prefill 的半截方案、PD 带来的新代价。

🎬 Roofline 可视化 + ITL 抖动对比动画

02 · 14 步全链路时序

从 client POST 到首个 SSE chunk 的完整路径：跨 6 进程、2 种语言、3 种通信协议。建立整章的骨架图。

🎬 可播放时序 + 🎯 点任何 step 冻结队列状态

03 · Router：双池路由 + bootstrap 注入

Rust 写的 PDRouter：WorkerRegistry、PolicyRegistry、execute_dual_dispatch、select_pd_pair（两次策略调用）、generate_room_id、tokio::join! 双发。

🎬 8 步请求流转 + 🎯 cache_aware vs power_of_two 对比

04 · Prefill Worker：三段流水线

BootstrapQueue + waiting_queue + InflightQueue。bootstrap_thread 如何收 D 的 ZMQ；send_kv_chunk 和 Mooncake transfer_worker 的源码逐行。

🎬 请求穿过 3 队列动画 + 实时源码对照

05 · Decode Worker：预分配 + 收货 + 首 token 交接

DecodeReqToTokenPool 的 pre_alloc 额度设计、DecodePreallocQueue.pop_preallocated 源码、send_metadata、commit 时的 bootstrap_room 串包校验。

🧠 ReqToTokenPool 对比模拟 + 🎬 D 侧 4 阶段流转

06 · KV Transfer & Bootstrap：三层协议

KVPoll 5 状态机、CommonKVBootstrapServer 6 个 HTTP 接口、_resolve_rank_mapping 组合爆炸、MetadataBuffers、staging buffer 异构 TP 优化。

🎯 P/D 双状态机交互探索 + ZMQ 消息 log

07 · 生产治理与排障

核心指标拆解、失败清理链路、调优环境变量、Router 动态扩缩容、EPD 扩展、10 条排障 checklist。

📊 模拟 metrics dashboard + 5 种故障场景切换

08 · Tokenizer 全链路：CPU 热路径解剖
