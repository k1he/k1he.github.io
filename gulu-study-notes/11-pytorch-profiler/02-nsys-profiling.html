§0最小示例 · 一条命令抓取

# 最简单的用法：包住你的 Python 程序
nsys profile \
    --trace=cuda,nvtx,osrt \
    --output=my_trace \
    --force-overwrite=true \
    python train.py

# 执行完毕后生成 my_trace.nsys-rep
# 拖到本地 Nsight Systems GUI 打开即可
就这么简单。不需要改任何代码，nsys 会在进程外自动采集所有 CUDA kernel、NVTX 标注和 OS Runtime 调用。执行结束后生成 .nsys-rep 文件，用 Nsight Systems GUI 打开就能看到完整时间线。

打开 trace 文件

# 本地（有 GUI 的机器）
nsys-ui my_trace.nsys-rep

# 或者直接用 Nsight Systems 应用程序打开
# File → Open → 选择 .nsys-rep 文件

远程服务器上的工作流

# Step 1: 在远程 GPU 服务器上抓取
ssh gpu-server
nsys profile --trace=cuda,nvtx,osrt --output=sglang_trace python -m sglang.launch_server ...

# Step 2: 把 nsys-rep 文件拖回本地
scp gpu-server:~/sglang_trace.nsys-rep ./

# Step 3: 本地 GUI 打开分析
nsys-ui sglang_trace.nsys-rep
远程抓取 + 本地分析是生产环境的常见工作流。服务器通常没有 GUI，但 nsys profile 只做采集（命令行），.nsys-rep 文件很小（通常几十 MB），拖回本地用 GUI 分析即可。

§1nsys profile 参数详解

nsys profile \
    --trace=cuda,nvtx,osrt,nvml,nccl  # 采集哪些维度
    --duration=30                     # 抓取 30 秒后自动停止
    --sample=cpu                      # CPU 采样（看 CPU 热点函数）
    --cpuctxsw=true                   # 记录 CPU 上下文切换
    --gpuctxsw=true                   # 记录 GPU 上下文切换
    --gpu-metrics-device=all          # 记录 GPU 利用率/功耗/温度
    --output=my_trace                # 输出文件名（自动加 .nsys-rep）
    --force-overwrite=true            # 覆盖已有文件
    --export=sqlite                 # 同时导出 SQLite 格式
    python my_script.py

--trace 参数选项

选项采集内容性能开销建议
cudaCUDA API 调用和 GPU kernel 执行+3-5%总是开
nvtxNVTX 标注区间+0%总是开（零开销）
osrtOS Runtime (malloc, pthread, read/write 等)+5-10%排查 CPU 瓶颈时开
nvmlGPU 利用率、显存、功耗、温度+1-2%推荐开
ncclNCCL 通信操作+2-3%多卡场景开
cudnncuDNN 内部 kernel 标注+2-3%排查 conv 时开
cublascuBLAS 内部 kernel 标注+2-3%排查 GEMM 时开
推荐组合：日常用 --trace=cuda,nvtx,osrt,nvml；多卡场景加 nccl；不要无脑全开——osrt 和 --sample=cpu 同时开会显著增加 trace 文件大小和采集开销。

常用参数速查

参数用途示例
--duration N采集 N 秒后自动停止--duration=60
-p PID对运行中的进程抓取-p 12345
--sample=cpuCPU 采样（火焰图）--sample=cpu
--cpuctxsw=true记录 CPU 上下文切换--cpuctxsw=true
--gpu-metrics-device=allGPU 利用率/功耗/温度--gpu-metrics-device=all
--export=sqlite导出 SQLite 方便脚本分析--export=sqlite
--force-overwrite=true覆盖已有输出文件--force-overwrite=true
-c cudaProfilerApi只在代码中 nsys 标记区间内采集-c cudaProfilerApi

§2对运行中进程抓取（核心场景！）

这是 Nsight Systems 相比 PyTorch Profiler 最大的优势：不需要改任何代码，不需要重启服务。

方式一：nsys profile -p

# 找到 SGLang 的 PID
pgrep -f sglang
# 或者
ps aux | grep sglang

# 对运行中的进程抓取 30 秒
nsys profile \
    --trace=cuda,nvtx,osrt,nvml \
    --duration=30 \
    --output=sglang_30s \
    -p 12345

# 30 秒后自动停止，生成 sglang_30s.nsys-rep

方式二：nsys start / stop（交互式）

# 启动采集会话
nsys start \
    --trace=cuda,nvtx,osrt,nvml \
    --output=sglang_interactive \
    -p 12345

# ... 此时你可以跑压测 ...
# 什么时候想停就停
nsys stop

# 生成 sglang_interactive.nsys-rep

方式三：多卡场景，每个 rank 一个 nsys

# 假设有 4 个 GPU rank，PID 分别为 1001-1004
for i in 1 2 3 4; do
    nsys profile \
        --trace=cuda,nvtx,nccl \
        --duration=30 \
        --output=rank_${i} \
        -p 100${i} &
done
wait

# 生成 rank_1.nsys-rep ~ rank_4.nsys-rep
# 在 GUI 中可以同时打开多个文件对比
生产环境最佳实践：先启动 SGLang 服务 → 用 bench_serving 或 bench_multiturn 开始压测 → 压测稳定后用 nsys profile -p <PID> --duration=30 抓取。这样抓到的是稳态负载下的 trace，不是启动阶段。

§3SGLang 压测全流程实战

以下是一个完整的"SGLang 推理服务 → 压测 → nsys 抓取 → 本地分析"工作流：

抓取时机选择

时机抓取内容用途
压测刚开始CUDA 初始化、模型加载、cache 预热排查启动慢问题
压测稳定期稳态推理 kernel、KV Cache、通信稳态性能分析（推荐）
长流量退化时host memory 碎片化、缓存效率退化排查累积型退化
切换前后对比优化前 vs 优化后的 trace验证优化效果
抓取时长建议：30-60 秒通常足够。--duration=30 抓稳态；--duration=60 抓包含冷启动的完整过程。不要抓太长（>5 分钟），trace 文件会很大，GUI 打开也会慢。

§4NVTX 标注 · 让 Trace 可读

没有标注的 trace 里，你只能看到 void cutlass_kernel<...> 这样的 kernel 名。加了 NVTX 标注后，trace 中会出现彩色区间，一眼定位"这是 prefill，那是 decode"。

Python（PyTorch 内置）

import torch.cuda.nvtx as nvtx

# 方式一：push/pop
nvtx.range_push("prefill_batch")
output = model(inputs)
nvtx.range_pop()

# 方式二：context manager (PyTorch 2.0+)
with torch.cuda.nvtx.range("decode_step"):
    token = model.generate(...)

# 方式三：mark（瞬时标记，不占区间）
nvtx.mark("cache_hit")

C/C++

#include <nvtx3/nvtx3.hpp>

// 方式一：push/pop
nvtx3::range_push("prefill_batch");
run_prefill(...);
nvtx3::range_pop();

// 方式二：RAII（自动 pop）
{
    auto range = nvtx3::scoped_range("decode_step");
    run_decode(...);
}  // 自动 pop

// 方式三：带颜色
nvtx3::range_push(nvtx3::color{0xFF0000}, "kv_transfer");

框架内置的 NVTX 标注

好消息是，PyTorch 和 SGLang 内部已经大量使用了 NVTX。即使你不手动添加，trace 里也会有：

  • PyTorch: aten::mm, aten::scaled_dot_product_attention 等自动标注
  • SGLang: forward_batch, decode_batch, kv_transfer 等内部标注
  • NCCL: 自动标注 AllReduce / AllGather 等操作
什么时候需要手动添加 NVTX：当你需要在 trace 中标记业务逻辑层面的区间时——比如"这 5 个 kernel 属于 HiCache L2 回填"或"这段是 EAGLE 投机推理"。框架内部只标注到 op 级别，业务级标注需要你自己加。

§5其他常用模式

5.1 GPU 指标采集

# 记录 GPU 利用率、显存带宽、功耗、温度
nsys profile \
    --trace=cuda,nvtx,nvml \
    --gpu-metrics-device=all \
    --duration=30 \
    -p 12345 \
    --output=gpu_metrics

GUI 中会显示 GPU SM 利用率、显存带宽利用率、功耗等曲线，与 kernel 时间线对齐。

5.2 命令行快速统计（nsys stats）

# 不用开 GUI，命令行直接看统计
nsys stats sglang_trace.nsys-rep

# 只看 GPU kernel 统计
nsys stats --report=gpkern sglang_trace.nsys-rep

# 只看 CUDA API 统计
nsys stats --report=cudaapi sglang_trace.nsys-rep

# 只看 NCCL 通信统计
nsys stats --report=nccl sglang_trace.nsys-rep

5.3 导出 SQLite 做自定义分析

# 采集时直接导出 SQLite
nsys profile --trace=cuda,nvtx --export=sqlite --output=my_trace python train.py

# 或对已有 nsys-rep 文件导出
nsys export --type=sqlite --output=my_trace my_trace.nsys-rep

# 用 Python 分析
import sqlite3
conn = sqlite3.connect("my_trace.sqlite")

# 查询最耗时的 10 个 kernel
df = conn.execute("""
    SELECT name, avg(duration) as avg_ms, count(*) as calls
    FROM CUPTI_ACTIVITY_KIND_KERNEL
    GROUP BY name
    ORDER BY avg_ms DESC
    LIMIT 10
""").fetchall()

5.4 代码控制的采集区间

# 只在 nsys 标记区间内采集，减少无关数据
# 启动时加 -c cudaProfilerApi
nsys profile -c cudaProfilerApi --trace=cuda,nvtx --output=controlled python train.py

# Python 代码中
import torch
torch.cuda.profiler.start()   # 开始采集
# ... 你关心的代码 ...
torch.cuda.profiler.stop()    # 停止采集
选择建议：日常用 -p PID --duration=30 最简单；需要精确控制区间时用 -c cudaProfilerApi；需要脚本分析时用 --export=sqlite。
