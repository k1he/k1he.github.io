§1数学定义

矩阵乘法 C = A × B

A
[M, K]
左矩阵
B
[K, N]
右矩阵
C
[M, N]
输出矩阵
C[i, j] = Σk=0K-1 A[i, k] · B[k, j]
一句话总结：每个输出元素 C[i,j] 是 A 的第 i 行和 B 的第 j 列的内积（dot product）——K 次乘法再求和。

Transformer 中到处是 GEMM

核心事实：一个 Transformer forward pass 里，90%+ 的 FLOPs 都是 GEMM。写好 GEMM kernel = 搞定 GPU 性能的大头。

§3计算量与内存量

计算量 (FLOPs)

FLOPs = 2 × M × N × K

为什么是 2？每个输出元素 C[i,j] 需要：

  • K 次乘法 (multiply)
  • K−1 次加法 (accumulate)
  • ≈ 2K 次浮点操作（业界惯例）

总共 M×N 个输出元素，故总 FLOPs = M×N×2K = 2MNK

示例 M=N=K=4096
137.4 GFLOP
2 × 4096³ = 1.37×1011
示例 M=N=K=8192
1.1 TFLOP
2 × 8192³ = 1.10×1012

内存量 (Bytes)

数据形状大小 (fp16)
读 AM × KM×K×2 bytes
读 BK × NK×N×2 bytes
写 CM × NM×N×2 bytes
合计(MK + KN + MN) × 2
M=N=K=4096 (fp16)
100.7 MB
3 × 4096² × 2 bytes
对比：137.4 GFLOP 计算量 vs 100.7 MB 内存量——计算远远"重"于数据搬运，这正是 GEMM 天生 compute-bound 的根源。

§4Arithmetic Intensity (AI) — 一个数字决定优化方向

定义

AI = FLOPs / Bytes = 2MNK / ((MK + KN + MN) × sizeof)

方阵简化 (M = N = K = n, fp16)

AI = 2n³ / (3n² × 2) = n / 3
n = 4096
1365 FLOP/B
4096 / 3 ≈ 1365
n = 1024
341 FLOP/B
1024 / 3 ≈ 341
Vector Add (对比)
0.17 FLOP/B
1 FLOP / 6 bytes (fp16 r+r+w)

Roofline Model

把 AI 和机器的「转折点」比较，就能判断 kernel 是 compute-bound 还是 memory-bound：

GEMM 是 compute-bound 的！AI = 1365 远大于 H100 的转折点 (~295)。这意味着瓶颈在于 Tensor Core 的吞吐量——优化重点是「喂饱计算单元」，不让它闲着等数据。
对照：Vector Add（AI=0.17）是典型的 memory-bound——怎么优化计算都没用，瓶颈在带宽。而 GEMM 正相反：数据搬运速度已经够了，关键是让 Tensor Core 满载运转。

§5三个维度的角色

M & N — 输出维度
决定 Parallelism
有多少个输出 tile → 有多少并行 programs
M/N 越大，GPU SM 越能被喂饱
K — 归约维度
决定 Loop Depth
一个 program 内部循环累加次数
不增加并行度，但增加每个 program 的工作量
关键 insight：M 和 N 决定了有多少并行的 programs（对应 GPU SM occupancy）；K 决定了每个 program 内部要循环多少次（对应计算密度）。两者共同决定总工作量 = 2MNK。

§6从数学到 Tiling 策略（预告）

一个 program 的工作流

  • 负责计算 C 的一个 [BLOCK_M × BLOCK_N] 子块
  • 需要读 A 对应的行 [BLOCK_M × K] 和 B 对应的列 [K × BLOCK_N]
  • 但 K 太大，无法一次全读入 SRAM → 切成 K / BLOCK_K 步循环
  • 每步读 A 的 [BLOCK_M × BLOCK_K] + B 的 [BLOCK_K × BLOCK_N]
  • 每步做一次小矩阵乘法（tl.dot），累加到 fp32 accumulator

核心循环伪代码

# 一个 program 负责 C 的一个 [BLOCK_M × BLOCK_N] tile
acc = zeros([BLOCK_M, BLOCK_N], dtype=fp32)   # fp32 累加器

for k_start in range(0, K, BLOCK_K):
    a_tile = tl.load(A[row_off : row_off+BLOCK_M, k_start : k_start+BLOCK_K])
    b_tile = tl.load(B[k_start : k_start+BLOCK_K, col_off : col_off+BLOCK_N])
    acc += tl.dot(a_tile, b_tile)   # → Tensor Core!

# 循环结束，写回 HBM
tl.store(C[row_off : row_off+BLOCK_M, col_off : col_off+BLOCK_N], acc.to(fp16))
Tiling 的本质：把一个巨大的 GEMM 拆成很多"小 GEMM"——每个小 GEMM 能完全利用 SRAM（L1 / shared memory），避免反复读写 HBM。这就是下几章要展开的核心优化策略。
