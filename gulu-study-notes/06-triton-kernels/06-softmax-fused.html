§1PyTorch 跑 softmax 在干什么 · 为什么慢

给一个矩阵 X [M, N]，做 row-wise softmax：

y[i, j] = exp(x[i, j] - max_k(x[i, k])) / Σ_k exp(x[i, k] - max_k(x[i, k]))

PyTorch 的执行路径（aten / cuDNN）

核心浪费：x 这个张量被读了4 遍。但其实只需要：读 1 遍、原地算完、写 1 遍。多读的 3 遍 HBM 是纯浪费——softmax 本来就是 memory-bound。

§2数学 · safe softmax + 数值稳定

朴素 softmax 的问题

y[j] = exp(x[j]) / Σ exp(x[i])

当 x[j]=100 时 exp(100) ≈ 2.7e43——fp16 直接溢出（max ~65504），连 fp32 也会丢失精度。

safe softmax · 减去最大值

m = max(x)
y[j] = exp(x[j] - m) / Σ exp(x[i] - m)

因为 x[j] - m ≤ 0，所以 exp(x[j] - m) ∈ (0, 1]——绝对不会溢出。分子分母同时除以 exp(m) 不影响结果，所以这是等价变换，不是近似。

所有工业 softmax 都用这个 trick。Triton kernel 也必须实现它，否则 inference 时 logits 一大就炸。

三个 reduce 步骤

  1. row max：找出每行最大值 m
  2. numerator + denominator：算 exp(x - m) 和它的和
  3. 除法：每个数除以行和

关键观察：如果整行能塞进寄存器/SMEM，三步可以一次扫完——这就是 Triton 能 fuse 的根本前提。

§3完整 kernel · 一个 program 处理一行

复制进 Colab，可直接跑 →
import torch, triton
import triton.language as tl

@triton.jit
def softmax_kernel(
    Y_ptr, X_ptr,
    stride_y_row, stride_x_row,
    N,                                # 列数
    BLOCK_N: tl.constexpr,            # 必须 ≥ N
):
    row = tl.program_id(0)        # 一个 program = 一行
    cols = tl.arange(0, BLOCK_N)
    mask = cols < N

    # 1. load 整行
    x = tl.load(
        X_ptr + row * stride_x_row + cols,
        mask=mask, other=-float("inf")   # 屏蔽位用 -inf，不影响 max
    )

    # 2. safe softmax 三步走
    x_max = tl.max(x, axis=0)              # 标量
    x_shifted = x - x_max                  # [BLOCK_N]
    numerator = tl.exp(x_shifted)
    denom = tl.sum(numerator, axis=0)       # 标量
    y = numerator / denom

    # 3. 写回
    tl.store(
        Y_ptr + row * stride_y_row + cols,
        y, mask=mask
    )

def softmax(x):
    M, N = x.shape
    y = torch.empty_like(x)
    # 选个 ≥ N 且是 2 的幂的 BLOCK_N
    BLOCK_N = triton.next_power_of_2(N)
    softmax_kernel[(M,)](
        y, x,
        y.stride(0), x.stride(0),
        N, BLOCK_N=BLOCK_N,
    )
    return y

# ---- 验证 ----
torch.manual_seed(0)
x = torch.randn(1823, 781, device="cuda")
y = softmax(x)
y_ref = torch.softmax(x, dim=1)
print("max abs diff:", (y - y_ref).abs().max().item())
# max abs diff < 1e-7

§4逐节解剖 · 4 个新知识点

① 1 program = 1 row · grid 是 1D = M

grid = (M,)
softmax_kernel[grid](...)
# M 个 program 并发，每个处理一行 N 个元素

为什么不是一行多个 program？因为 reduce（求 max、求 sum）需要看到整行——拆给多个 program 就要跨 program 通信，那比 PyTorch 的多 kernel 还慢。

限制：N 不能超过 BLOCK_N，BLOCK_N 不能超过 SM 寄存器+SMEM 容量。所以本 kernel 适用范围 N ≤ ~64K。N 更大需要多 program 协作 + cross-program reduce（高级技巧，本章不展开）。

② mask 用 -inf 填充 · 不影响 max

x = tl.load(..., other=-float("inf"))

BLOCK_N 通常大于真实 N（例如 N=781、BLOCK_N=1024）。多出来的 243 个位置 load 出来用什么填？

  • 填 0 → 在 max 时可能错误地成为最大值（如果真实数全是负的）
  • 填 -inf → max 永远不会选它，sum 时 exp(-inf)=0 也不影响

这是常见的 reduce kernel 技巧。后面 attention 也会用。

③ tl.max / tl.sum / tl.exp · 张量级 reduce

x_max = tl.max(x, axis=0)
denom = tl.sum(numerator, axis=0)

axis=0 是 BLOCK 内部那一维（[BLOCK_N] 上 reduce）。结果是标量。Triton 编译器把它翻成 SM 内的 warp shuffle + atomic，几个指令搞定。

tl.exp(x) 直接对每个元素算 exp（element-wise）。Triton 会用 GPU 的快速近似 __expf（误差 ~ 2 ULP，足够 inference 用）。

④ triton.next_power_of_2 · 选 BLOCK_N

BLOCK_N = triton.next_power_of_2(N)

Triton 要求 BLOCK_N 在 reduce 操作中是 2 的幂（warp shuffle 需要）。所以 N=781 时 BLOCK_N=1024。多出来的 243 用 mask 屏蔽。

编译时确定的常量：每出现一个新的 N，Triton 会缓存编译结果（按 BLOCK_N 分类）。生产环境如果 N 离散（几十种值），autotune 会替你管 cache。

§5online softmax 预告 · 当一行装不下

现在的 kernel 假设 BLOCK_N ≥ N。如果 N=128K（比如长上下文 attention），一行装不进 SMEM。怎么办？

朴素：扫两遍

m = -inf
for tile in chunks(x):     # pass 1: 找 max
    m = max(m, max(tile))

s = 0
for tile in chunks(x):     # pass 2: 算 numerator 和 denom
    e = exp(tile - m)
    s += sum(e)

for tile in chunks(x):     # pass 3: 写回 (e/s)
    write(exp(tile - m) / s)

3 趟扫完整行——读 X 三遍、写 Y 一遍。还是浪费。

online softmax · 一趟搞定

关键 insight：扫到第 i 个 tile 时，当前 running max m_i 和当前 running denom l_i 可以联合维护：

# 来一个新 tile x_new
m_new = max(m_i, max(x_new))
l_new = l_i * exp(m_i - m_new) + sum(exp(x_new - m_new))
                  ↑                       ↑
            旧 denom 修正系数        新 tile 贡献
m_i, l_i = m_new, l_new
核心 trick：当 running max 更新时，用 exp(m_old - m_new) 修正之前累加的 denom。一趟扫完就能拿到最终的 m 和 l。这就是 FlashAttention 的核心数学技巧——下一章 T4 攻 attention 时全套用。

本章不展开 online softmax 的完整代码（需要循环 + 状态维护），先把它放进脑子里："reduce 也能 streaming 做"。

§6benchmark · 现在 Triton 终于赢了

复制运行 →
import triton
@triton.testing.perf_report(
    triton.testing.Benchmark(
        x_names=["N"],
        x_vals=[128 * i for i in range(2, 100, 8)],
        line_arg="provider",
        line_vals=["torch", "triton"],
        line_names=["PyTorch", "Triton"],
        ylabel="GB/s",
        plot_name="softmax",
        args={"M": 4096},
    ))
def benchmark(M, N, provider):
    x = torch.randn(M, N, device="cuda")
    quantiles = [0.5, 0.2, 0.8]
    if provider == "torch":
        ms = triton.testing.do_bench(lambda: torch.softmax(x, axis=1), quantiles=quantiles)
    else:
        ms = triton.testing.do_bench(lambda: softmax(x), quantiles=quantiles)
    gbps = lambda ms: 2 * x.numel() * x.element_size() * 1e-9 / (ms * 1e-3)
    return [gbps(t) for t in ms]

benchmark.run(print_data=True)

当一行装不下时，用 running max + 修正系数一趟扫完 · 是 FlashAttention 的灵魂
