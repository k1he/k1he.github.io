§1朴素 attention 写法 · 它为什么慢、为什么吃显存

给 Q、K、V 三个 [N, d] 矩阵（N 是 seq_len，d 是 head_dim），attention 的标准定义：

S = Q @ K.T          # [N, N]   ← 物化巨大的 attention matrix
P = softmax(S/√d)    # [N, N]
O = P @ V            # [N, d]

问题：[N, N] 矩阵

seq_len NS 大小 (fp16)HBM 流量（写 S 读 P）
10242 MB4 MB
409632 MB64 MB
16384512 MB1 GB
655368 GB16 GB
痛点 1：O(N²) 的显存占用——N=64K 时 S 矩阵 8GB，单条 attention 就把 H100 占一半。
痛点 2：S 写一次 + 读一次 = 16GB HBM 流量，attention 变成完全 memory-bound。

FlashAttention 的目标：不物化 S，把它"流式"做完。

§2三个核心方程 · online softmax 的 attention 版

回忆 T3 的 online softmax：扫到第 i 段时，维护 running max m 和 running denom l。FlashAttention 在它基础上多维护一个东西——running output O。

设定

把 K、V 沿 seq 维切成块：K1, K2, ..., KT（每块 [BK, d]）；V 同样。Q 切成 [BM, d] 的 tile。一个 program 处理 Q 的一个 tile，沿 K/V 的 T 块循环。

状态变量

m: [BM]      # 当前每行的 running max
l: [BM]      # 当前每行的 running denom (Σ exp(s - m))
O: [BM, d]   # 当前每行的 running output

来一个新的 K/V 块时（核心三步）

# 1. 算这块的 attention scores
S_ij = Q_i @ K_j.T / √d         # [BM, BK]

# 2. 更新 max（用新块的 max 和旧 m 比）
m_new = max(m, rowmax(S_ij))     # [BM]

# 3. 修正系数 alpha · 调整旧 l 和旧 O
alpha = exp(m - m_new)            # [BM]   ← 旧值要"打折"
P_ij = exp(S_ij - m_new)          # [BM, BK]

# 4. 更新 l 和 O
l_new = alpha * l + rowsum(P_ij)
O_new = alpha[:, None] * O + P_ij @ V_j

m, l, O = m_new, l_new, O_new

循环结束后归一化

O = O / l[:, None]
核心 insight——alpha = exp(m_old - m_new) 是把"以前那种 max 算的 softmax"换算成"现在 max 下的 softmax"的修正系数。因为 softmax 减一个常数等价，所以可以延迟到最后再归一化。S 矩阵从未真正存在过。

显存与流量

实现S 矩阵物化显存HBM 流量
朴素是O(N²)O(N² + Nd)
FlashAttention否（在 SMEM 里流式）O(Nd)O(Nd) (再加一点 K/V 重读)

N=64K、d=128：朴素显存 8GB → FlashAttention 16MB（500x 节省）。HBM 流量也大幅下降——这就是 FA 又快又省显存的双赢。

§3完整 kernel · 简化版 forward（causal mask）

这是教学版 FA forward（单 head、causal mask、float16）。完整 FA2 还会处理 masking、varlen、bwd、bf16 等，但核心循环就是这个。

复制进 Colab，T4 上 N=4096、d=64 的输入约 5ms →
import torch, math, triton
import triton.language as tl

@triton.jit
def flash_attn_fwd(
    Q_ptr, K_ptr, V_ptr, O_ptr,
    sm_scale,
    N, d,
    stride_qm, stride_qd,
    stride_km, stride_kd,
    stride_vm, stride_vd,
    stride_om, stride_od,
    BLOCK_M: tl.constexpr,        # Q tile size
    BLOCK_N: tl.constexpr,        # K/V tile size
    D: tl.constexpr,              # head_dim, 编译期
):
    pid_m = tl.program_id(0)              # 哪个 Q tile

    # 1. 加载 Q tile（整个外层循环只读一次）
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_d = tl.arange(0, D)
    q = tl.load(
        Q_ptr + offs_m[:, None] * stride_qm + offs_d[None, :] * stride_qd,
        mask=offs_m[:, None] < N, other=0.0
    )                                            # [BM, D]

    # 2. 初始化 running 状态
    m_i = tl.full([BLOCK_M], -float("inf"), dtype=tl.float32)
    l_i = tl.zeros([BLOCK_M], dtype=tl.float32)
    acc = tl.zeros([BLOCK_M, D], dtype=tl.float32)

    # 3. 沿 K/V 循环（causal: 只看 j ≤ i 的 K/V）
    end_n = (pid_m + 1) * BLOCK_M       # causal mask 的 K 范围上界
    for start_n in range(0, end_n, BLOCK_N):
        offs_n = start_n + tl.arange(0, BLOCK_N)

        # 加载 K, V tile
        k = tl.load(
            K_ptr + offs_n[:, None] * stride_km + offs_d[None, :] * stride_kd,
            mask=offs_n[:, None] < N, other=0.0
        )
        v = tl.load(
            V_ptr + offs_n[:, None] * stride_vm + offs_d[None, :] * stride_vd,
            mask=offs_n[:, None] < N, other=0.0
        )

        # 4. S = Q @ K.T / sqrt(d)
        s = tl.dot(q, tl.trans(k)) * sm_scale     # [BM, BN]

        # 5. 应用 causal mask
        causal = offs_m[:, None] >= offs_n[None, :]
        s = tl.where(causal, s, -float("inf"))

        # 6. online softmax 三步
        m_new = tl.maximum(m_i, tl.max(s, axis=1))
        alpha = tl.exp(m_i - m_new)
        p = tl.exp(s - m_new[:, None])

        # 7. 修正旧 acc 和 l，再加上新贡献
        l_i = alpha * l_i + tl.sum(p, axis=1)
        acc = acc * alpha[:, None] + tl.dot(p.to(v.dtype), v)
        m_i = m_new

    # 8. 最终归一化 + 写回
    acc = acc / l_i[:, None]
    tl.store(
        O_ptr + offs_m[:, None] * stride_om + offs_d[None, :] * stride_od,
        acc.to(tl.float16),
        mask=offs_m[:, None] < N
    )

def flash_attention(q, k, v):
    N, d = q.shape
    o = torch.empty_like(q)
    sm_scale = 1.0 / math.sqrt(d)
    BLOCK_M, BLOCK_N = 64, 64
    grid = (triton.cdiv(N, BLOCK_M),)
    flash_attn_fwd[grid](
        q, k, v, o, sm_scale, N, d,
        q.stride(0), q.stride(1),
        k.stride(0), k.stride(1),
        v.stride(0), v.stride(1),
        o.stride(0), o.stride(1),
        BLOCK_M=BLOCK_M, BLOCK_N=BLOCK_N, D=d,
    )
    return o

# ---- 验证 ----
torch.manual_seed(0)
N, d = 512, 64
q = torch.randn(N, d, device="cuda", dtype=torch.float16)
k = torch.randn_like(q); v = torch.randn_like(q)
o = flash_attention(q, k, v)

# reference (causal)
S = (q.float() @ k.float().T) / math.sqrt(d)
mask = torch.tril(torch.ones(N, N, device="cuda")).bool()
S = S.masked_fill(~mask, -float("inf"))
o_ref = (torch.softmax(S, dim=-1) @ v.float()).to(torch.float16)
print("max abs diff:", (o.float() - o_ref.float()).abs().max().item())
# max abs diff < 1e-2 (fp16 数值范围内)

§4逐节解剖 · 6 个关键点

① 一个 program 处理 Q 的一个 tile · K/V 全程被它扫一遍

grid = (cdiv(N, BLOCK_M),)
pid_m = tl.program_id(0)            # 我负责 Q 的第 pid_m 个 tile

这是 FA 的关键调度选择：外层并行 = Q tile，内层串行 = K/V tile。原因是 K/V 每块都要被这个 Q tile 看到（reduce 性质），如果跨 program 拆 K/V 就要写中间结果。

② Q tile 整个外层循环只读一次

# 在 for 循环之外加载 q
q = tl.load(...)
for start_n in range(0, end_n, BLOCK_N):
    ...

Q 加载到寄存器/SMEM 后，T 次 K/V 循环里都用这同一个 q——这就是"Q stays in SRAM"。HBM 流量上 Q 只读了 1 次（不是 T 次）。

③ tl.trans · 转置 K 不真转

s = tl.dot(q, tl.trans(k)) * sm_scale

tl.trans(k) 不会真去 HBM 转置 K——Triton 编译器会调整 dot 的 layout，免费把 K 转过来。这就是为什么我们直接 load K 的原始 layout，然后 trans 它。

④ causal mask 用 tl.where + -inf

causal = offs_m[:, None] >= offs_n[None, :]
s = tl.where(causal, s, -float("inf"))

把不该看的位置的 score 设成 -inf，softmax 后这些位置的权重精确为 0。注意 mask 在 max 之前应用，否则 row max 会被 -inf 干扰。

FA2/FA3 的额外优化：causal 时，对于 K tile 全部在 Q tile 右侧的 (start_n > end_m) 直接 break——这类 tile 全部 mask 掉，跳过能省一半算力。本教学版没做这个优化。

⑤ 修正系数 alpha · 三处一起改

alpha = tl.exp(m_i - m_new)
l_i = alpha * l_i + tl.sum(p, axis=1)
acc = acc * alpha[:, None] + tl.dot(p.to(v.dtype), v)
m_i = m_new

这就是 online softmax 的核心。当 m 更新时，旧 l 和旧 acc 都要乘 alpha "打折"——因为它们之前是按旧 m 算的 exp，现在要换算成按新 m 的 exp。

四行的顺序重要：
① m_new 必须先算（用旧 m）
② alpha 用 m_i - m_new
③ l 和 acc 用 alpha 修正
④ 最后才覆盖 m_i = m_new
错一行结果就全错。

⑥ 最终一次性归一化

acc = acc / l_i[:, None]

循环过程中 acc 一直没除，等所有 K/V tile 扫完，最终一次除完事。这避免了循环里反复做除法的精度损失，也减少了几条指令。

import triton

def torch_attn(q, k, v):
    d = q.shape[-1]
    S = (q.float() @ k.float().T) / math.sqrt(d)
    mask = torch.tril(torch.ones_like(S)).bool()
    S = S.masked_fill(~mask, -float("inf"))
    return (torch.softmax(S, dim=-1) @ v.float()).to(q.dtype)
