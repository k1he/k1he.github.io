04按平面切故障，排查速度会快很多

查得到，搬不动

都正常，模型仍错

记忆句：Mooncake 数据面保证“这些字节到了”；上层必须保证“这些字节恰好是这个请求、这些 layer、这些 token 的 KV，而且现在可以读”。

05TransferEngineImpl::init：启动时到底创建了什么

transfer_engine_impl.cpp:77Mooncake f7330a635747
  1. 尝试把 RLIMIT_NOFILE 提到 hard limit；失败只警告，连接规模大时才暴露 fd 问题。
  2. 解析 local_server_name。P2PHANDSHAKE 模式会动态寻找可用 TCP port，并把最终 ip:port 作为本节点 identity。
  3. 创建 TransferMetadata 与 MultiTransport，然后用 addRpcMetaEntry 发布 RPC 描述。
  4. MC_FORCE_TCP 存在时提前只安装 TCP；若编译时没有 USE_TCP 直接失败。
  5. 否则根据编译能力、拓扑和配置安装 RDMA/TCP/NVLink/Ascend 等 transport。
metadata_conn_string 决定“节点怎样互相发现”，transport 决定“payload 怎样移动”。SGLang 传入 P2PHANDSHAKE 时没有中心 metadata server，但每个 engine 仍有一个用于握手和 segment 描述交换的 RPC endpoint。

07一次请求真正跨过的两个状态机

控制面状态机

segment name → RPC metadata → SegmentID/BufferDesc → 缓存/刷新/关闭。它决定 target offset 对应哪台机器的哪段 MR。

数据面状态机

BatchDesc → TransferTask → Slice → PENDING/POSTED → CQE → SUCCESS/FAILED → task/batch terminal。

两者的连接点是 TransferRequest.target_id + target_offset。target_id 失效是 metadata 问题；offset/rkey/CQE 错误是数据面问题。后续两课会分别追到函数体。
