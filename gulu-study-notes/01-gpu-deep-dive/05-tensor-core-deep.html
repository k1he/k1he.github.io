Tensor Core 深度解析 · 为什么矩阵乘法有专用引擎 第一章 · 05/08

CUDA Core 是“标量 ALU”，Tensor Core 是“矩阵乘累加工厂”。LLM 里的 Linear、Attention、MoE 最终都变成 GEMM，所以 Tensor Core 决定了训练/推理的上限。本篇从一条 MMA 指令讲到 warpgroup MMA、FP8/FP4、tiling pipeline，以及为什么普通 CUDA 代码跑不满它。

§1为什么需要 Tensor Core：GEMM 是 AI 的“发动机”

Transformer 里最贵的算子几乎都能写成矩阵乘法：

Linear:      Y = XW
Attention:   QK^T,  softmax(QK^T)V
MLP:         gate_up = XW, down = act(gate)·up·W
MoE:         token dispatch 后，每个 expert 还是 GEMM

普通 CUDA Core 每条指令做少量 FMA；Tensor Core 一条指令做一个小矩阵的乘累加：

D = A × B + C

这就是为什么 FP32 CUDA core 峰值只有几十 TFLOPS，而 FP16/FP8 Tensor Core 峰值能到数百/上千 TFLOPS。

§2MMA 指令模型：warp 共同发起的小矩阵乘

Tensor Core 并不是“每个 thread 单独调用一次”。典型 MMA 是 一个 warp 或 warpgroup 协作：每个 lane 持有 A/B/C 的一小片 fragment，硬件把它们组合成矩阵 tile。

// PTX 形态示意：m16n8k16 的 half 矩阵乘，累加到 fp32
mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32
  {d0,d1,d2,d3}, {a0,a1,a2,a3}, {b0,b1}, {c0,c1,c2,c3};

m16n8k16 是什么

符号含义对 GEMM 的对应
m16输出 tile 的 M 维 16 行通常是 token/block 行
n8输出 tile 的 N 维 8 列通常是输出 channel 列
k16内积维 K 每次推进 16hidden_dim 方向分块
row.colA row-major，B col-major决定 shared memory layout
f32.f16.f16.f32D/C FP32，A/B FP16低精度输入，高精度累加
Fragment 是最容易误解的点：程序员看见的是每个 thread 几个寄存器；硬件看见的是整个 warp 的寄存器集合。MMA 指令把 32 个 lane 的 fragment 拼成矩阵，送进 Tensor Core。

架构年份Tensor Core 重点支持格式对 LLM 的意义

Hopper H1002022FP8、Transformer Engine、wgmmaFP8 E4M3/E5M2、BF16、FP16大模型训练/推理吞吐大涨；FlashAttention-3 依赖 wgmma

代际升级不是只加 FLOPS：真正改变 kernel 写法的是指令模型和数据搬运能力。例如 Hopper 的 wgmma + TMA 让“一个 warpgroup 算，一个 TMA 搬”的流水线成为主流；Blackwell 又把低精度格式推进到 FP4。

§4数字格式：BF16、FP8、FP4 到底牺牲了什么

Tensor Core 的高吞吐依赖低精度。低精度不是“随便少几位”，而是在动态范围、精度、累加格式之间取舍。

格式位数特点常用位置风险
FP321 sign + 8 exp + 23 mantissa范围和精度都强累加、loss、少量敏感算子慢、占显存
TF328 exp + 10 mantissaFP32 范围，降低 mantissaAmpere 默认加速 FP32 GEMM精度略低
BF168 exp + 7 mantissa范围同 FP32，精度低训练/推理主流小差异表达弱
FP165 exp + 10 mantissa精度比 BF16 高，范围小推理、部分训练溢出/下溢更敏感
FP8 E4M34 exp + 3 mantissa精度相对好，范围较小activation/weight需要 scale
FP8 E5M25 exp + 2 mantissa范围更大，精度更低gradient/动态范围大处量化误差大
FP44 bit极致压缩Blackwell 推理/训练新方向必须强依赖 scale 和校准

Scale 是 FP8/FP4 的“生命线”

真实值 x  →  x_scaled = x / scale  →  cast to FP8/FP4
计算时 Tensor Core 读低精度值，累加通常仍用 FP16/FP32
输出再乘回 scale 或进入下一层 scale

Transformer Engine 的工作就是动态选择这些 scale，决定哪些张量用 E4M3、哪些用 E5M2，以及何时回退到 BF16/FP16。

§5Tiling Pipeline：Tensor Core 不等数据，数据要提前送到嘴边

一颗 Tensor Core 很快，瓶颈常常变成“把 A/B tile 从 HBM 搬到寄存器”。高性能 GEMM pipeline 通常长这样：

for k_tile in K:
  async copy global → shared memory    // cp.async / TMA
  wait previous tile ready
  load shared → register fragment      // ldmatrix
  mma / wgmma                          // Tensor Core 计算
  double-buffer shared memory          // 搬下一块时算当前块

§6Hopper 的 wgmma async：从 warp 到 warpgroup

Hopper 引入 wgmma：warpgroup-level matrix multiply-accumulate。一个 warpgroup = 4 个 warp = 128 threads。它的关键变化：

  • 粒度更大：128 线程协作发起更大的矩阵 tile。
  • 异步：wgmma 发出后可以和后续指令重叠，需要 barrier/commit/wait 管理。
  • 更适合 FlashAttention-3：warpgroup 负责矩阵乘，另一些 warp/TMA 负责搬运，流水线更深。
// PTX 形态示意，不是完整可编译代码
wgmma.mma_async.sync.aligned.m64n128k16.f32.f16.f16
wgmma.commit_group.sync.aligned;
wgmma.wait_group.sync.aligned 0;
写 wgmma 难在哪：不是调用指令，而是满足它对 shared memory layout、barrier、warpgroup 协作、寄存器压力、TMA pipeline 的所有约束。绝大多数项目通过 CUTLASS/CuTe、Triton、FlashAttention 内核间接使用。

§7LLM kernel 视角：哪些地方吃 Tensor Core，哪些地方吃不到

算子是否主要用 Tensor Core原因常见瓶颈
Prefill Q/K/V Linear是大 batch/长序列 GEMM算力 + HBM，通常 compute-bound
Decode Linear部分batch 小时退化成 GEMV，复用少权重 HBM bandwidth
QK^T Attention是tile 化矩阵乘K/V 读取 + softmax pipeline
Softmax否max/sum/exp/reduce，多用 CUDA Core/SFUreduction、数值稳定、寄存器
Sampling Top-k/Top-p否排序/扫描/随机采样vocab 维读取 + reduce
MoE Expert GEMM是本质仍是分组 GEMMtoken dispatch、small GEMM 合并
LayerNorm/RMSNorm否reduce + elementwise内存带宽和 reduction

所以推理系统不是“只看 Tensor Core 峰值”

Prefill 阶段通常能把 Tensor Core 喂得很满；decode 阶段 batch 小、每步读权重/KV 多，Tensor Core 经常吃不饱。因此服务系统的优化重点是 continuous batching、prefix cache、CUDA Graph、KV layout、spec decode，而不只是换更高 TFLOPS 的卡。

§8带走的八句话

  1. Tensor Core 是矩阵乘专用引擎，不是更快的普通 CUDA Core。
  2. MMA 是协作指令：warp/warpgroup 的 lane fragments 拼成矩阵 tile。
  3. 低精度输入 + 高精度累加 是主流：FP16/BF16/FP8 输入，FP32 或 FP16/FP32 累加。
  4. 峰值 FLOPS 的前提是数据喂得上：tiling、SMEM、TMA、double buffer 都是喂饭系统。
  5. Hopper 的 wgmma 把粒度扩大到 warpgroup，让异步矩阵乘和异步搬运更深度重叠。
  6. Transformer Engine 的本质是管理低精度 scale，让 FP8/FP4 尽量不炸精度。
  7. Prefill 更容易吃满 Tensor Core，decode 往往被 HBM/KV/launch 卡住。
  8. 真正的 kernel 优化是系统工程：指令、layout、搬运、同步、调度缺一不可。
