Hopper 架构详解 · H100 为什么是 LLM 时代的分水岭 第一章 · 06/08

Hopper 不是“更大的 Ampere”。它把大模型训练/推理的几个核心痛点——数据搬运、低精度、attention、跨 SM 协作、多卡互联——都做成了硬件级能力。本篇围绕 H100/GH100：TMA、wgmma、Thread Block Cluster、DSMEM、FP8 Transformer Engine、NVLink 4。

一句话定位：A100 让 BF16/TF32 成为主流，H100 让 FP8、异步矩阵乘、硬件级二维拷贝、cluster 级协作进入主流。

§2Hopper SM：围绕 Tensor Core pipeline 重构

Hopper SM 仍然有 4 个 sub-partition、warp scheduler、register file、LD/ST、SFU、Tensor Core、L1/Shared Memory。但新增/强化的核心是：

  • wgmma：warpgroup 级异步矩阵乘，4 warp 协作。
  • TMA：Tensor Memory Accelerator，硬件级多维 copy。
  • 更大的 shared memory：每 SM 最高 228KB，适合更大 tile。
  • async barrier：让 copy/compute 的依赖关系可被硬件调度。

§3TMA：Tensor Memory Accelerator，把“搬砖”交给硬件

Ampere 时代常用 cp.async：每个 warp/thread 发起 global → shared 的异步 copy。Hopper 引入 TMA，可以用少量线程触发大块多维 tensor copy：

传统 cp.async：很多 lane 分别搬 16B/128B 小片
TMA：一个 descriptor 描述张量形状/stride/box，硬件 copy engine 搬整块 tile

TMA descriptor 包含什么

字段作用为什么比手写地址好
base pointerglobal memory 起始地址统一描述源 tensor
rank / shape1D-5D 张量形状支持矩阵/多维 tile
stride每个维度步长硬件处理 non-contiguous layout
box size要搬的 tile 大小一次 copy 一个逻辑 tile
swizzle写入 shared memory 的布局变换减少 bank conflict，满足 wgmma layout
TMA 是 Hopper kernel 的分水岭：FlashAttention-3、CUTLASS 3.x/CuTe 风格 kernel 都围绕 TMA + wgmma 设计 pipeline。手写很多 cp.async 的 Ampere kernel 迁移到 Hopper，通常要重写才能吃满 H100。

§4Thread Block Cluster 与 DSMEM：SM 之间开始“近距离协作”

传统 CUDA 的同步/共享内存作用域主要在一个 block 内。Hopper 引入 Thread Block Cluster：多个 thread block 被保证调度到一组相邻 SM，可以使用 cluster-level barrier 和 Distributed Shared Memory（DSMEM）。

传统 block

  • block 内线程可 __syncthreads()
  • block 内可共享 SMEM
  • block 与 block 间不能强同步
  • 跨 block 协作通常要回 global memory

Hopper cluster

  • 多个 block 组成 cluster
  • cluster 内可 barrier
  • 可访问彼此的 shared memory（DSMEM）
  • 适合 producer-consumer / 大 tile 协作
// CUDA cooperative groups 概念示意
namespace cg = cooperative_groups;
__global__ void kernel(...) {
  cg::cluster_group cluster = cg::this_cluster();
  // block rank in cluster
  int rank = cluster.block_rank();
  cluster.sync();
  // 可进行 cluster-level 协作
}
对 LLM 的意义：大型 attention/GEMM tile 可能超过单 SM 的 SMEM/warp 资源。Cluster 让多个 SM 近距离分工：有的 block 负责搬运，有的负责计算，有的负责 reduce。但编程复杂度高，通常由库封装。

§5FP8 Transformer Engine：低精度不是简单 cast

Hopper 的第四代 Tensor Core 支持 FP8（E4M3/E5M2），并配套 Transformer Engine 自动管理精度：

  • E4M3：mantissa 多一点，适合 activation/weight。
  • E5M2：exponent 多一点，范围大，适合 gradient 或动态范围更大的张量。
  • scale 管理：每个 tensor 或 block 记录 scale，把真实值映射到 FP8 可表达范围。
  • 自动回退：敏感层/算子可用 BF16/FP16，避免数值炸掉。
x_fp8 = quantize(x / scale, format=E4M3)
y = matmul_fp8(x_fp8, w_fp8, scale_x, scale_w)
accumulator 通常使用更高精度，输出再进入下一层 scale
FP8 的收益与代价：收益是吞吐更高、显存/带宽更低；代价是需要校准/scale/异常值处理。LLM 推理中 FP8 权重、FP8 KV Cache 都能降 HBM 压力，但必须确认模型精度和服务稳定性。

§6Hopper 为什么特别适合 Attention

Attention kernel 同时需要：

  • 大规模矩阵乘：QK^T 和 P·V → Tensor Core/wgmma。
  • 多维 tile 搬运：K/V block 从 HBM 到 SMEM → TMA。
  • online softmax：max/sum 保持在 register，避免 materialize 整个 attention matrix。
  • 深 pipeline：搬下一块 K/V 时计算当前块 → async barrier。

§8带走的八句话

  1. Hopper 的核心不是单纯堆 SM，而是把大模型关键路径做成硬件能力。
  2. TMA 把多维 tile 搬运交给硬件，减少 warp 参与和地址计算。
  3. wgmma 把矩阵乘推进到 warpgroup 粒度，支持更深异步 pipeline。
  4. 更大 SMEM + async barrier 让 copy/compute overlap 成为主流写法。
  5. FP8 Transformer Engine 让低精度不只是 cast，而是 scale 管理系统。
  6. Thread Block Cluster/DSMEM 让跨 SM 近距离协作成为可能。
  7. H100 特别适合 attention：TMA 搬 K/V，wgmma 算 QK/PV，register 做 online softmax。
  8. 从 A100 到 H100，kernel 写法发生代际变化：Ampere cp.async 思维 → Hopper TMA+wgmma 思维。
