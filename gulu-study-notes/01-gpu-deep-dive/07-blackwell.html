Blackwell 架构详解 · 从单卡到 AI Factory 第一章 · 07/08

Blackwell 的关键词不是“更快一点”，而是“把一整柜 GPU 当成一颗巨型加速器”。B200/GB200 把双 die 封装、FP4 Transformer Engine、更大的 HBM3e/L2、更强 NVLink/NVL72 推到中心位置。本篇强调公开资料下的架构直觉：它为什么为万亿参数推理而生。

读 Blackwell 的正确姿势：不要只看单卡 TFLOPS。真正的跃迁是：低精度把字节数压下去，HBM/L2 把本地数据喂上去，NVLink/NVL72 把多卡通信开销压下去。

§2双 die + NV-HBI：一颗 GPU 里其实有“两座城市”

单颗 GPU die 不能无限变大：reticle limit、良率、功耗、布线都会卡住。Blackwell 采用两个大 die 通过高速芯片间互联连接，对软件暴露为一个统一 GPU（具体产品形态由平台决定）。

这对程序员意味着什么

  • 理想情况下仍把它当一张 GPU 用，CUDA runtime 抽象掉 die 边界。
  • 实际性能仍受内部 fabric、L2 slice、本地 HBM 访问模式影响——高性能库会做拓扑感知优化。
  • 单卡变大后，multi-GPU 的切分粒度也改变：一个 “GPU” 已经是封装内多 die 协作。

§3FP4 与第二代 Transformer Engine：为了推理的“字节战争”

Hopper 的 FP8 已经把 16-bit 减半。Blackwell 进一步引入 FP4/FP6，并强化 Transformer Engine。核心逻辑：

显存占用：FP16 2B → FP8 1B → FP4 0.5B
HBM 流量：理论上同步下降
Tensor Core 吞吐：低精度模式更高
但数值风险：scale、outlier、校准、累加精度变得更重要
格式每值字节优势代价推理场景
BF16/FP162B稳定、生态成熟带宽/容量压力大质量优先、敏感层
FP81B质量/效率折中需要 scale主流高吞吐推理/训练
FP60.75B介于 FP8 与 FP4生态更早期特定模型压缩
FP40.5B容量和带宽极致节省量化误差/scale 更敏感大模型推理、MoE 权重
FP4 不是“所有东西都 4 bit”：通常是权重/activation 某些路径低精度，accumulator、normalization、logits、部分敏感层保留更高精度。真正可用的 FP4 推理依赖框架、kernel、校准策略三者配合。

§4HBM3e + 大 L2：更长上下文和更大 batch 的底座

B200 级别公开规格给到约 192GB HBM3e 和 8TB/s 带宽。这对 LLM 推理非常直接：

  • 更大权重：单卡能放更大模型 shard，TP 度数可降低。
  • 更长 KV Cache：长上下文和更高并发时不那么容易 OOM。
  • 更高 decode 吞吐：decode 常 memory-bound，HBM 带宽直接影响 tokens/s。
  • 更大 L2：权重 tile、KV hot pages、routing metadata 更容易片上命中。

KV Cache 算例

假设模型每 token KV = 128KB（上一章算例）
192GB HBM 理论可容纳 token 数 = 192GB / 128KB ≈ 1,572,864 tokens
扣除权重、workspace、碎片后仍能显著提升长上下文/并发空间。

如果 FP8 KV：每 token KV 约减半 → 容量翻倍
如果 FP4 KV：理论再减半 → 但精度/算法风险更高

§5NVLink 5 / NVL72：把 72 个 GPU 变成一个机柜级加速器

Blackwell 的系统野心体现在 GB200 NVL72：72 个 Blackwell GPU + Grace CPU + NVSwitch 构成一个高带宽 rack。对超大模型推理来说，关键不是“能连起来”，而是：

  • all-reduce 延迟/带宽是否能支撑高 TP。
  • expert parallel / tensor parallel / pipeline parallel 的拓扑映射是否足够高效。
  • 跨 GPU KV/activation/权重交换是否不把 decode 拖死。

§6可靠性、安全、解压：数据中心不是跑 benchmark

Blackwell 面向的是 AI factory：长时间运行、多租户、大模型服务。公开资料强调了多项系统能力：

能力直觉为什么服务端关心
RAS/可靠性增强错误检测、隔离、恢复能力千卡级集群任一组件故障都会影响训练/推理任务
机密计算保护模型权重和用户数据企业私有模型、敏感数据推理
解压/数据处理引擎减轻 CPU/GPU 数据预处理压力训练数据管道、压缩权重/数据流
Grace CPU 协同CPU/GPU 超级芯片形态减少主机瓶颈，提高整机能效

§8带走的八句话

  1. Blackwell 的重点是规模化：单 GPU 更大，机柜级互联也更强。
  2. 双 die 是突破单 die 极限的工程解，但也要求内部 fabric 足够快。
  3. FP4/FP6/FP8 是字节战争：为了降低权重和 KV 的 HBM 流量。
  4. 第二代 Transformer Engine 管的是 scale 和混合精度策略，不是简单 cast。
  5. HBM3e 192GB/8TB/s 对 decode 很关键，因为 decode 常被带宽卡住。
  6. 大 L2 提高热数据命中，对权重 tile、KV hot page、metadata 都有价值。
  7. NVL72 把优化目标从“单节点”扩展到“机柜”，TP/EP/PP 都要拓扑感知。
  8. 硬件越强，软件越不能偷懒：kernel、量化、调度、通信栈必须同步升级。
