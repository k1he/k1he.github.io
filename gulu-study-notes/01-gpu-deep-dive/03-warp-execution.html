§1Warp 为什么是 32

warp = 32 个线程的"步操队"——同一 warp 的 32 线程共享一条指令、一个 PC，每个 cycle 一起前进一步。这是 NVIDIA 从 G80（2006）就定下的常数，至今未变。

三个理由

  • 电路级别的扇出：1 条指令需要广播到 N 个 ALU。N=32 时，时序、布线、功耗都"刚刚好"。N=64（AMD CDNA 一直走 wave64）会让单个 lane 的物理距离更长，时钟难提；N=16 太小，每条指令的"开销 / 收益"不划算。
  • 寄存器读端口：每条指令最多 3 个源操作数 × 32 线程 × 4 B = 384 B/cycle。对应 SRAM 读端口宽度，正好匹配 SM 内部 crossbar。
  • 访存合并粒度：32 个线程访问 4 字节连续地址 = 128 字节，正好是 GDDR/HBM 的一个最小事务（cache line）。这是访存"coalescing"为什么对齐 128B 的根因。
对比 AMD：CDNA(MI300) 默认 wave64，但 RDNA(消费卡) 改成 wave32 了——RDNA 团队也认了 wave32 在很多负载下更高效。所以 32 这个数字不是 NVIDIA 拍脑袋，是工程上的稳定最优解。

§2SIMT vs SIMD：相邻但不同

很多文档说 GPU 是 SIMD，严格来说不对——NVIDIA 把它命名为 SIMT（Single Instruction, Multiple Threads）。差异看似细微，写 kernel 的体验完全不同。

SIMD（CPU AVX-512）SIMT（GPU warp）
编程模型1 个线程 + 矢量寄存器 __m51232 个"线程"，每线程像在独立跑标量代码
指令长度1 条 vec 指令 = 16 个 float1 条 SASS 指令 = 32 lane 同步执行
分支需要程序员手写 mask硬件用 active mask 自动 mask
寻址通常连续；gather/scatter 慢每 lane 自己算地址；无分散惩罚（但有 coalescing 偏好）
视觉感受"我在 packed 操作""我在写 32 个独立线程"
SIMT 是 SIMD 的"高级抽象"：硬件还是矢量执行，但编译器/硬件帮你处理了 mask 和 gather/scatter——你写的是 if (tid < n) data[tid] = ...，看起来像 32 个独立线程；硬件实际是 1 条指令 + 32-bit active mask。

§3Warp Divergence · 当 32 个线程"想各干各的"

所有 SIMT 系统的"原罪"——只要 warp 内 32 线程走了不同分支，硬件只能串行执行每个分支。

__global__ void kernel(int* x){
  int tid = threadIdx.x;
  if (tid % 2 == 0) {
      x[tid] = a();   // 偶数线程
  } else {
      x[tid] = b();   // 奇数线程
  }
}

硬件做了什么

避免 divergence 的实战技巧

  • 条件按 warp 而非 thread 划分：if (warpIdx % 2 == 0) → 整个 warp 走同一路径，0 divergence。
  • 用 predicated execution：短的 if 编译器会自动转成 SEL（select）指令，无分支。
  • 排序消除 divergence：sort by branch tag 后 launch，使同一 warp 内 lane 倾向同分支。
  • mask 化 reduce：reduce 时用 __activemask() + __shfl_sync 处理掉部分活跃情况。
Volta 之前 vs 之后：Volta 引入 Independent Thread Scheduling 后，divergence 的"重新合流"（reconvergence）变得更智能；但开销仍在——只是更少出现死锁，不是更便宜。

§4Independent Thread Scheduling（Volta+）

Volta 之前 warp 内每个 lane 共享 PC（program counter），这导致一种"经典 GPU bug"：

__device__ int x = 0;
if (lane == 0) {
    while (atomicCAS(&lock, 0, 1) != 0);  // lane 0 抢锁
}
// 期望：lane 1-31 等 lane 0 拿到锁
// Pre-Volta 实际：死锁！

原因：pre-Volta 整个 warp 共享 PC，lane 0 在 spin 时其他 31 个 lane 也卡在同一指令——它们永远等不到 lane 0 进入锁后的 release 指令。

Volta 的修复

Volta 给每个 lane 独立的 PC 和 stack。warp 仍按 SIMT 跑，但 scheduler 可以"在 warp 内切换线程子集"——比如先让 lane 1-31 跑一会儿，再切回 lane 0 spin 一次。

历史包袱：Volta 之前的 CUDA 代码经常用 __shfl(...)（无 _sync 后缀）的隐式同步形式。Volta 之后这些 API deprecated，必须显式传 mask + 用 _sync 版本。否则在 Volta+ 上行为未定义。

§5Occupancy · 一个 SM 上能放多少 warp

Occupancy = 实际 resident warps / 硬件最大 warps。Hopper 每 SM 最多 64 warp，A100 也是 64，T4 是 32。

四个限制因素

资源H100/SM 上限每 thread/block 占多少
线程数2048（= 64 warp × 32）blockDim.x × blockDim.y
Block 数321（每 block）
Register65536每 thread × thread/block
Shared Memory228 KB每 block 静态 + dynamic

算一个例子：

kernel: blockDim = 256 threads = 8 warp
        每 thread 用 64 个 register
        每 block 用 16 KB SMEM

→ Register 限制: 65536 / (256 × 64) = 4 block/SM
→ SMEM 限制:    228 / 16 = 14 block/SM
→ Block 数限制:  32 block/SM
→ Thread 限制:   2048 / 256 = 8 block/SM

实际 = min(4, 14, 32, 8) = 4 block/SM
       = 4 × 8 = 32 warp resident
       = 32/64 = 50% occupancy

瓶颈是寄存器。要把 occupancy 推到 100%，要么把 thread/block 从 256 减到 128，要么把 register 从 64 减到 32。

但 100% Occupancy 不等于最快

常见误区：以为 occupancy 越高越好。 事实：很多 LLM kernel 跑在 25-50% occupancy 反而最快。 原因：
  • 每线程更多寄存器 → 更激进的 unrolling、更深的 ILP
  • 更少 warp → SMEM 配额更大，能装更大 tile
  • Tensor Core 已经把 SM 喂饱了，不需要那么多 warp 隐藏延迟
FlashAttention-2 H100 kernel: 每线程 232 个 register，occupancy 仅 12.5%——但跑得最快。

§6Latency Hiding · 为什么需要那么多 warp

HBM 访问 ~400 cycle，FMA 仅 4 cycle——如果一个 warp stall 在 HBM load，SM 闲 100×。

解决：同一 SM 同时驻留多个 warp，scheduler 在它们之间快速切换：

Little 定律给出的 warp 数

需要 warp 数 = 内存延迟 × 内存带宽 / 单 warp 单次访存量
            ≈ 400 cycle × (3.35 TB/s × 1 SM 份额) / 128 B
            ≈ 16~32 warp/SM 才能打满 HBM
但有 Tensor Core 的 GEMM 不靠 warp 隐藏延迟：因为 wgmma 自己是异步的，它内部就把延迟隐藏了。这就是为什么 FlashAttention-3 用 12.5% occupancy 也能 90% peak。

§7Warp 原语：shfl / vote / match

warp 内 32 线程能直接互相交换数据/状态，不走 SMEM、不走寄存器——通过专用 datapath（cross-lane shuffle network）。这些是 reduce/softmax/sort 的常用基石。

shfl 系列：lane 间数据搬运

// 同一 warp 内的 lane 互相借数据
__shfl_sync(mask, val, srcLane);          // 从 srcLane 读取
__shfl_up_sync(mask, val, delta);         // 从 lane-delta 处读取
__shfl_down_sync(mask, val, delta);       // 从 lane+delta 处读取
__shfl_xor_sync(mask, val, laneMask);     // XOR 模式（蝶式 reduce）

典型用法：warp 内 sum reduce

// 单条指令树形 reduce，比 SMEM 版快 3-5×
float warp_sum(float v) {
  for (int delta = 16; delta >= 1; delta /= 2)
    v += __shfl_xor_sync(0xffffffff, v, delta);
  return v;  // 全 lane 都拿到 sum
}

vote / ballot：condition 聚合

// 整个 warp 内有多少 lane 条件成立？
unsigned mask = __ballot_sync(0xffffffff, x > 0);
int count = __popc(mask);    // popcount = 1 的位数

// 全 lane 都成立？
bool all_pos = __all_sync(0xffffffff, x > 0);
// 任一成立？
bool any_pos = __any_sync(0xffffffff, x > 0);

match（Volta+）：相等性聚合

// 找出 warp 内有多少 lane 持有相同值（用于稀疏 reduce、ATG）
unsigned same = __match_any_sync(0xffffffff, key);
unsigned all  = __match_all_sync(0xffffffff, key, &pred);
这些原语全部走专用网络，不占 SMEM bank、不消耗 LD/ST cycle，每个 cycle 1 op，是最便宜的 warp 内通信方式。FlashAttention 的 online softmax max/sum 全靠它们；vLLM 的 sampling top-k 也用它们。

§8带走的七句话

  1. warp = 32 线程一指令——这是 GPU 一切设计（coalescing、bank 数、寄存器宽度）的"长度单位"。
  2. SIMT 是带 mask 的 SIMD——硬件帮你处理 divergence，但不免费。
  3. Warp Divergence 损失 = 路径数——分支分得越细越慢，按 warp 划分而非按 thread。
  4. Volta 后 lane 各有 PC——可写 spin lock，但 __shfl 必须用 _sync 版本。
  5. Occupancy ≠ 越高越好——LLM kernel 常以 25-50% 跑得最快（更多 reg、更大 tile）。
  6. Latency Hiding 靠多 warp 切换——HBM 400 cycle 用 16-32 个 warp 凑掩盖。但 Tensor Core 自带异步，依赖 warp 切换的程度大幅降低。
  7. warp 原语（shfl/ballot/match）零成本通信——所有快 reduce、softmax、sampling 的内核都重度依赖。
