§1从 Triton 过来的你，需要知道什么变了

Triton 你已经会的CUDA 对应新增的复杂度
programThreadblock (Block/CTA)Block 内还有 threads
program_id(0)blockIdx.x还有 threadIdx.x
BLOCK_SIZE (编译器决定线程数)blockDim.x (你决定)需要手动选
tl.arange 自动向量化每个 thread 处理 1 个(或几个)元素手动循环
tl.load/store (自动 coalesce)手动保证 coalesced access可能出错
核心对应关系：Triton 的 1 个 program 对应 CUDA 的 1 个 Block。但 Triton 隐藏了 Block 内部的线程分工——CUDA 里你要亲自安排。

§2CUDA 的三层并行模型

Grid → Block → Thread 层次结构

  • Grid：所有 blocks 的集合。维度：gridDim.x / y / z
  • Block (CTA)：一组可以协作的线程。维度：blockDim.x / y / z。Block 内线程共享 shared memory，可以 __syncthreads()
  • Thread：最小执行单位。每个 thread 有自己的 registers + local memory

现代 GPU 关键数字 (A100 / H100)

Max threads/block1024 Max blocks/SM32（视资源占用，有时 16） 典型选择128 或 256 threads per block Shared mem/block最高 164 KB (H100) / 164 KB (A100 可配)

§3坐标系统 — threadIdx, blockIdx, blockDim

// 每个 thread 都能访问这些内置变量:
int tid  = threadIdx.x;    // 我在 Block 内的编号 [0, blockDim.x)
int bid  = blockIdx.x;     // 我所在 Block 的编号 [0, gridDim.x)
int bdim = blockDim.x;     // 一个 Block 里有多少 threads

// 全局唯一编号:
int global_id = bid * bdim + tid;

对比 Triton

Triton — 一个 program 处理 BLOCK_SIZE 个元素
# Triton
pid = tl.program_id(0)
offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
CUDA — 一个 thread 处理 1 个元素
// CUDA
int idx = blockIdx.x * blockDim.x + threadIdx.x;
// 或者一个 thread 处理多个元素 (grid-stride loop)

§4Kernel 函数定义与启动

// __global__ = 可以从 CPU 调用、在 GPU 上执行
__global__ void my_kernel(float* input, float* output, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        output[idx] = input[idx] * 2.0f;
    }
}

// 启动方式: <<<grid_size, block_size>>>
int n = 1000000;
int block_size = 256;
int grid_size = (n + block_size - 1) / block_size;  // cdiv
my_kernel<<<grid_size, block_size>>>(d_input, d_output, n);

关键概念

  • __global__：kernel 声明——表示这个函数从 CPU 调用、在 GPU 上执行
  • <<<grid, block>>>：启动配置（对应 Triton 的 kernel[grid](...)）
  • 返回类型必须是 void
  • 每个 thread 执行一遍 kernel 函数体——所以需要 if (idx < n) 边界检查
Triton 对比：Triton 中写 mask = offsets < n 做边界检查，CUDA 中用 if (idx < n)——本质相同，只是粒度不同（Triton 是 block 级向量化 mask，CUDA 是 thread 级标量 if）。

§5多维 Block 和 Grid

// 2D block (常用于矩阵操作)
dim3 block(16, 16);    // 16×16 = 256 threads per block
dim3 grid(
    (N + 15) / 16,     // X 方向有多少个 block
    (M + 15) / 16      // Y 方向有多少个 block
);
kernel<<<grid, block>>>(...);

// kernel 内部:
int col = blockIdx.x * blockDim.x + threadIdx.x;
int row = blockIdx.y * blockDim.y + threadIdx.y;
if (row < M && col < N) {
    C[row * N + col] = ...;
}

§6Warp — 你必须知道的隐藏层

Triton 完全隐藏了这一层，但在 CUDA 中它决定了性能。

基本事实

  • 32 threads = 1 warp
  • 一个 warp 内的 32 个 thread 同步执行同一条指令（SIMT — Single Instruction, Multiple Threads）
  • Block 被自动划分为 warps：256 threads = 8 warps
  • Warp 是 GPU 实际调度的最小单位

性能关键推论

现象原因后果
分支发散 (Warp Divergence)同一 warp 内 if-else → 两个分支都要执行性能减半（串行化）
内存合并 (Coalesced Access)同一 warp 内 threads 访问连续地址一次内存事务（高带宽利用率）
天然同步Warp 内 32 threads lock-step 执行不需要 __syncthreads()，可用 __shfl_sync 原语
当你听到 "warp divergence" 或 "bank conflict" 时，本质都是 warp 这一层的问题。Triton 编译器自动避免了大部分 warp 级问题——CUDA 里你要自己注意。

§7Grid-Stride Loop — 一个 thread 处理多个元素

不好 — 每个 thread 只处理一个元素，grid 要很大
__global__ void add_bad(float* a, float* b,
                       float* c, int n) {
    int idx = blockIdx.x * blockDim.x
            + threadIdx.x;
    if (idx < n)
        c[idx] = a[idx] + b[idx];
}
好 — Grid-stride loop，每个 thread 处理多个元素
__global__ void add_good(float* a, float* b,
                        float* c, int n) {
    int idx = blockIdx.x * blockDim.x
            + threadIdx.x;
    int stride = blockDim.x * gridDim.x;
    for (int i = idx; i < n; i += stride) {
        c[i] = a[i] + b[i];
    }
}
Grid-stride loop 的好处：grid 可以小于数据量，线程复用减少 launch overhead。适用于超大数据集。

但在 GEMM 中我们通常不用这个——每个 block 负责一个固定的输出 tile。

§8完整代码：从 CPU 到 GPU 的完整流程

#include <cuda_runtime.h>
#include <stdio.h>

__global__ void vector_add(float* a, float* b, float* c, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) c[idx] = a[idx] + b[idx];
}

int main() {
    int n = 1 << 20;  // 1M elements
    size_t bytes = n * sizeof(float);

    // Host memory
    float *h_a = (float*)malloc(bytes);
    float *h_b = (float*)malloc(bytes);
    float *h_c = (float*)malloc(bytes);

    // Init
    for (int i = 0; i < n; i++) { h_a[i] = 1.0f; h_b[i] = 2.0f; }

    // Device memory
    float *d_a, *d_b, *d_c;
    cudaMalloc(&d_a, bytes);
    cudaMalloc(&d_b, bytes);
    cudaMalloc(&d_c, bytes);

    // Copy H→D
    cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, h_b, bytes, cudaMemcpyHostToDevice);

    // Launch
    int block_size = 256;
    int grid_size = (n + block_size - 1) / block_size;
    vector_add<<<grid_size, block_size>>>(d_a, d_b, d_c, n);

    // Copy D→H
    cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost);

    // Verify
    printf("c[0] = %f (expected 3.0)\n", h_c[0]);

    // Cleanup
    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    free(h_a); free(h_b); free(h_c);
    return 0;
}
