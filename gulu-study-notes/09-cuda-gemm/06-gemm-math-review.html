这些在 Triton 教程中讲过。这节重点是 CUDA 特有的分工方式——thread 怎么分配、数据怎么复用。

§2CUDA GEMM 的分工层次

CUDA GEMM 的核心：三层分工 —— Grid → Block → Thread，每层有自己的数据复用策略。

Triton vs CUDA 的关键区别：Triton 的一个 program 直接拥有整个 [BM × BN]。CUDA 里需要把它再细分给每个 thread，每个 thread 只负责 [TM × TN] 个输出。

§3数据复用分析（CUDA 视角）

GEMM 优化的本质：让每个数据元素被使用尽可能多次。CUDA 有两层复用：

Level 1 — Block 级复用（Shared Memory）

总复用次数

A 元素: 被 BN/TN 个 thread 使用 × 每个 thread 用 TN 次 = BN 次
B 元素: 被 BM/TM 个 thread 使用 × 每个 thread 用 TM 次 = BM 次

例：BM=BN=128 → 每个元素被复用 128 次！这就是 tiled GEMM 快的原因。

§4参数选择的约束

参数典型值约束条件
BM64 ~ 256受 shared memory 容量限制
BN64 ~ 256受 shared memory 容量限制
BK8 ~ 64BK × (BM + BN) × sizeof ≤ shared memory
TM4 ~ 8TM × TN = register tile → 占 register 数量
TN4 ~ 8同上
threads/block128 ~ 256(BM/TM) × (BN/TN)

约束 1：Shared Memory

// 每步 K-loop 加载两个 tile 到 shared memory
shared_bytes = (BM × BK + BK × BN) × 4 bytes

// 例: BM=128, BN=128, BK=32
= (128 × 32 + 32 × 128) × 4
= 8192 × 4 = 32 KB ← OK (A100 有 164 KB/SM)

约束 2：Register

// 每个 thread 的 register 占用
accumulators: TM × TN       // 存储输出 tile
A fragment:   TM              // 从 shared 读的 A 列
B fragment:   TN              // 从 shared 读的 B 行
Total: TM × TN + TM + TN

// 例: TM=8, TN=8
= 8 × 8 + 8 + 8 = 80 registers/thread
× 256 threads = 20,480 registers/block ← OK (65,536 可用/SM)
参数选择是一个多约束优化问题：增大 BM/BN 提高复用，但消耗更多 shared memory；增大 TM/TN 提高 register 复用，但减少 occupancy。需要平衡。

§5GEMM Kernel 的完整数据流

核心循环模式：加载 → 同步 → 计算 → 同步 → 下一轮加载。两次 __syncthreads() 是必须的：第一次保证加载完成，第二次保证计算完成后才能覆盖 shared memory。

§6对比 Triton 的 K-loop

步骤TritonCUDA
加载 tile tl.load（整个 tile 一步） threads 协作 + __syncthreads
存储位置 编译器自动选 shared / register 手动 __shared__ 声明
内层计算 tl.dot（整个 tile matmul） 每 thread 做 TM×TN 的小 matmul
同步 不需要（单 program） __syncthreads × 2（加载前后）
指针移动 ptrs += BLOCK_K * stride 手动计算新偏移
Triton 的 tl.dot 在 CUDA 里展开成：for kk (BK 步) × for tm × for tn 的三重循环。Triton 帮你做了所有 thread 协调工作，CUDA 需要手动完成。

§8带走

  1. CUDA GEMM = Grid(blocks) × Block(threads) × Thread(register tile) 三层分工
  2. Block tile [BM×BN] → shared memory 复用；Thread tile [TM×TN] → register 复用
  3. K-loop：加载 → 同步 → 计算 → 同步 的循环
  4. 参数受 shared memory + register 双重约束，需要平衡复用率与 occupancy
