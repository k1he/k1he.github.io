C1 · 线程索引 · threadIdx / blockIdx 的所有花样

CUDA 编程的第一个技巧：把 thread 编号正确映射到数据地址。这节覆盖 1D/2D/3D 索引、Row-major 寻址、边界检查——全是手动的。

§1 一维索引（最基础）

int idx = blockIdx.x * blockDim.x + threadIdx.x;

边界检查——当数据量 n 不能被 blockDim.x 整除时：

if (idx < n) {  // 边界检查
    out[idx] = in[idx];
}

§2 二维索引（矩阵操作必备）

dim3 block(16, 16);  // 256 threads
dim3 grid((N+15)/16, (M+15)/16);

__global__ void kernel(float* C, int M, int N) {
    int col = blockIdx.x * blockDim.x + threadIdx.x;  // X → 列
    int row = blockIdx.y * blockDim.y + threadIdx.y;  // Y → 行
    if (row < M && col < N) {
        C[row * N + col] = ...;  // row-major 寻址
    }
}
注意 CUDA 的坐标惯例：x 通常对应列（内层），y 对应行（外层）。这和矩阵的 [row, col] 刚好相反！

§3 Row-Major 寻址详解

Matrix M×N, stored in 1D array:
  element[row][col] → array[row * N + col]

Example: 4×8 matrix
  [row=2, col=5] → index = 2*8 + 5 = 21

Memory layout:
  row 0: [ 0, 1, 2, 3, 4, 5, 6, 7]
  row 1: [ 8, 9,10,11,12,13,14,15]
  row 2: [16,17,18,19,20,21,22,23]  ← element at index 21
  row 3: [24,25,26,27,28,29,30,31]

对比 Triton

# Triton 用 stride 概念:
ptr + offs_m[:, None] * stride_m + offs_n[None, :] * stride_n
# 对 row-major: stride_m = N, stride_n = 1
# 所以就是: ptr + row * N + col

§4 Stride 的概念

// 对于 row-major M×N 矩阵:
int stride_row = N;  // 跨一行需要跳 N 个元素
int stride_col = 1;  // 跨一列只需跳 1 个元素

// 通用寻址:
int index = row * stride_row + col * stride_col;
这就是 Triton 里 a.stride(0) 和 a.stride(1) 的含义。PyTorch tensor 的 stride 直接告诉你跨一个维度要跳多少元素。

Column-Major（Fortran order）

int stride_row = 1;
int stride_col = M;
int index = row * stride_row + col * stride_col;  // = row + col*M

§5 Thread-to-Data 映射的三种模式

模式 1：一对一（1 thread = 1 element）

int idx = blockIdx.x * blockDim.x + threadIdx.x;
out[idx] = in[idx] * 2;
  • 最简单
  • 需要 N 个线程（可能太多）

模式 2：Grid-stride loop（1 thread = 多个 element）

for (int i = idx; i < n; i += gridDim.x * blockDim.x)
    out[i] = in[i] * 2;
  • 灵活
  • 适合数据量不确定的情况

模式 3：Tile-based（1 block = 1 tile）

// Block (tid_y, tid_x) 负责 output tile 内的一个元素
int row = blockIdx.y * TILE_M + threadIdx.y;
int col = blockIdx.x * TILE_N + threadIdx.x;
  • GEMM 的标准模式
  • 对应 Triton 的 "一个 program 一个 tile"

§6 实战：矩阵转置

一个展示索引映射的经典例子：

__global__ void transpose(float* out, const float* in, int M, int N) {
    int col = blockIdx.x * blockDim.x + threadIdx.x;
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    if (row < M && col < N) {
        out[col * M + row] = in[row * N + col];
        // 读: in[row][col] (row-major)
        // 写: out[col][row] (也是 row-major，但行列互换)
    }
}
这个 naive 版本有 coalescing 问题——稍后会在内存章节优化。

§7 三维索引（batched 操作）

dim3 block(16, 16, 1);
dim3 grid((N+15)/16, (M+15)/16, batch_size);

__global__ void batched_op(float* data, int M, int N, int batch_size) {
    int col   = blockIdx.x * blockDim.x + threadIdx.x;
    int row   = blockIdx.y * blockDim.y + threadIdx.y;
    int batch = blockIdx.z;  // 第几个 batch

    if (row < M && col < N && batch < batch_size) {
        int idx = batch * M * N + row * N + col;
        data[idx] = ...;
    }
}
batch 维度映射到 gridDim.z——每个 z-slice 处理一个 batch，互相独立。

§8 常见错误

错误原因后果修复
没有边界检查 idx >= n 越界写入/读取 if (idx < n)
x/y 搞反 col/row 混淆 结果错乱 x=col, y=row
blockDim 不是 32 的倍数 warp 对不齐 性能差 用 128/256
grid 太小 数据没处理完 部分结果丢失 cdiv

§9 带走

  1. global_id = blockIdx.x * blockDim.x + threadIdx.x — CUDA 的核心公式
  2. row-major: index = row * N + col
  3. 2D kernel: x→col, y→row（注意这个惯例）
  4. GEMM 用 tile-based 映射: 1 block = 1 output tile
  5. 永远加边界检查 if (row < M && col < N)
