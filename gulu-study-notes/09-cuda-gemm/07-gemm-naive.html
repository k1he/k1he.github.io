C6 · GEMM Naive · 每个线程算一个输出元素 CUDA GEMM 系列 · 7/15

最简单的 CUDA GEMM：一个 thread 负责 C[row][col] 一个元素，内层循环遍历 K。能跑、能验证、但性能只有 cuBLAS 的 1-5%。

§1思路

最直觉的方式：thread (row, col) 负责计算 C[row][col] = Σk A[row][k] × B[k][col]

每个 thread 做三件事：

  1. 从 A 中读取一整行的 K 个元素：A[row][0], A[row][1], ..., A[row][K-1]
  2. 从 B 中读取一整列的 K 个元素：B[0][col], B[1][col], ..., B[K-1][col]
  3. 逐个相乘、累加得到 C[row][col]
一句话总结：每个 thread = 一个内积（dot product）。整个 grid 有 M×N 个 threads，恰好覆盖 C 的所有元素。

§2完整 Kernel

__global__ void gemm_naive(
    const float* A, const float* B, float* C,
    int M, int N, int K
) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;

    if (row < M && col < N) {
        float sum = 0.0f;
        for (int k = 0; k < K; k++) {
            sum += A[row * K + k] * B[k * N + col];
        }
        C[row * N + col] = sum;
    }
}

// Launch:
dim3 block(16, 16);  // 256 threads per block
dim3 grid((N + 15) / 16, (M + 15) / 16);
gemm_naive<<<grid, block>>>(d_A, d_B, d_C, M, N, K);
核心模式：2D block + 2D grid 覆盖整个输出矩阵。每个 thread 用一个 for 循环完成内积。

§3逐行解读

代码行含义解读
row = blockIdx.y * blockDim.y + threadIdx.y 全局行索引 2D indexing：y 轴 = 行。blockIdx.y 确定 block 在行方向的位置，threadIdx.y 确定 block 内的行偏移
col = blockIdx.x * blockDim.x + threadIdx.x 全局列索引 2D indexing：x 轴 = 列。惯例：x=列、y=行（与数学矩阵下标对齐）
if (row < M && col < N) 边界检查 grid 可能比矩阵大（向上取整），越界的 thread 什么都不做
A[row * K + k] A[row][k] Row-major 1D 索引：行 × 列宽 + 列偏移
B[k * N + col] B[k][col] 同上：第 k 行、第 col 列
float sum = 0.0f 累加器 存在 register 中（最快的存储层级），内循环 K 次只写这一个变量
C[row * N + col] = sum 写回结果 循环结束，一次 global store

§4为什么这么慢？— 访问模式分析

问题 1：A 的访问模式

// Thread (row, col) 在 K-loop 中读取:
A[row*K + 0], A[row*K + 1], ..., A[row*K + K-1]

// 同一 warp 中 32 个 threads (same row, col=0..31):
//   在同一个 k 步，全部读 A[row*K + k] — 同一个地址！
//   → L1 cache hit after first thread → broadcast OK ✓
A 的读取其实还行：同行的 32 个 threads 读同一地址，L1 cache 广播一次即可。

问题 2：B 的访问模式

// Thread (row, col=0..31) 在同一个 k 步读取:
B[k*N + 0], B[k*N + 1], ..., B[k*N + 31]

// → 连续地址，128 bytes 对齐 → coalesced ✓
等等，B 也是 coalesced？对！同一 warp 内读取的 B 地址是连续的。
那为什么还是这么慢？

问题 3：真正的问题 — 重复读 Global Memory

总内存访问量（从 HBM 读取）:

每个 C[row][col] 的计算需要读 K 个 A 元素 + K 个 B 元素
总共: M × N × 2K 次读取

理论最小值（只读一次 A、一次 B）:
M × K + K × N

浪费倍数:
A 的每一行被 N 个 threads 各自独立读 → 重复 N 次
B 的每一列被 M 个 threads 各自独立读 → 重复 M 次
核心问题不是 coalescing，而是重复读取：每个 A/B 元素被从 global memory 反复读取 N/M 次。即使 L2 cache 能缓解一部分，对于大矩阵，cache 装不下，绝大部分还是要回 HBM。

§5性能分析

矩阵大小Naive GEMMcuBLAS效率
M=N=K=1024~2 TFLOPS~150 TFLOPS1.3%
M=N=K=2048~3 TFLOPS~170 TFLOPS1.8%
M=N=K=4096~4 TFLOPS~180 TFLOPS2.2%

为什么这么惨？

有效算术强度 (AI_effective):

每个 thread: 2K FLOPs / (K × 4 + K × 4) bytes = 2K / 8K = 0.25 FLOP/Byte

GPU 的 roofline 平衡点（例: A100）:
312 TFLOPS / 2 TB/s = 156 FLOP/Byte

差距: 0.25 vs 156 → 差了 600 多倍！
→ 完全被 HBM 带宽卡死（memory-bound 到极致）
即使 L2 cache 能帮一些忙（同一行的 threads 可能 cache hit），对于大矩阵，工作集远超 L2 容量（A100 L2 = 40 MB，但 4096×4096 矩阵 = 64 MB），大量 miss 不可避免。

§6引出优化方向

如果同一行的 threads 能共享 A 的同一行数据...

而不是各自独立去 global memory 读...

那就需要一个 block 内所有 threads 都能访问的共享存储...

→ Shared Memory!

§7完整可运行代码

// gemm_naive.cu — 完整可运行代码
// 编译: nvcc -O2 -o gemm_naive gemm_naive.cu
// 运行: ./gemm_naive

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <cuda_runtime.h>

// ============================================================
// Naive GEMM Kernel
// ============================================================
__global__ void gemm_naive(
    const float* A, const float* B, float* C,
    int M, int N, int K
) {
    int row = blockIdx.y * blockDim.y + threadIdx.y;
    int col = blockIdx.x * blockDim.x + threadIdx.x;

    if (row < M && col < N) {
        float sum = 0.0f;
        for (int k = 0; k < K; k++) {
            sum += A[row * K + k] * B[k * N + col];
        }
        C[row * N + col] = sum;
    }
}

// ============================================================
// CPU 参考实现（用于验证正确性）
// ============================================================
void gemm_cpu(
    const float* A, const float* B, float* C,
    int M, int N, int K
) {
    for (int i = 0; i < M; i++) {
        for (int j = 0; j < N; j++) {
            float sum = 0.0f;
            for (int k = 0; k < K; k++) {
                sum += A[i * K + k] * B[k * N + j];
            }
            C[i * N + j] = sum;
        }
    }
}

// ============================================================
// 工具函数
// ============================================================
void init_matrix(float* mat, int size) {
    for (int i = 0; i < size; i++) {
        mat[i] = (float)(rand() % 100) / 100.0f;
    }
}

bool verify(const float* gpu, const float* cpu, int size) {
    for (int i = 0; i < size; i++) {
        if (fabs(gpu[i] - cpu[i]) > 1e-3) {
            printf("Mismatch at %d: GPU=%.6f, CPU=%.6f\n", i, gpu[i], cpu[i]);
            return false;
        }
    }
    return true;
}

// ============================================================
// main
// ============================================================
int main() {
    const int M = 1024, N = 1024, K = 1024;
    size_t bytes_A = M * K * sizeof(float);
    size_t bytes_B = K * N * sizeof(float);
    size_t bytes_C = M * N * sizeof(float);

    // 分配 host 内存
    float* h_A = (float*)malloc(bytes_A);
    float* h_B = (float*)malloc(bytes_B);
    float* h_C = (float*)malloc(bytes_C);
    float* h_C_ref = (float*)malloc(bytes_C);

    // 初始化数据
    srand(42);
    init_matrix(h_A, M * K);
    init_matrix(h_B, K * N);

    // 分配 device 内存
    float *d_A, *d_B, *d_C;
    cudaMalloc(&d_A, bytes_A);
    cudaMalloc(&d_B, bytes_B);
    cudaMalloc(&d_C, bytes_C);

    // 拷贝到 GPU
    cudaMemcpy(d_A, h_A, bytes_A, cudaMemcpyHostToDevice);
    cudaMemcpy(d_B, h_B, bytes_B, cudaMemcpyHostToDevice);

    // Launch kernel
    dim3 block(16, 16);
    dim3 grid((N + 15) / 16, (M + 15) / 16);

    // Warmup
    gemm_naive<<<grid, block>>>(d_A, d_B, d_C, M, N, K);
    cudaDeviceSynchronize();

    // 计时
    cudaEvent_t start, stop;
    cudaEventCreate(&start);
    cudaEventCreate(&stop);

    const int repeat = 10;
    cudaEventRecord(start);
    for (int i = 0; i < repeat; i++) {
        gemm_naive<<<grid, block>>>(d_A, d_B, d_C, M, N, K);
    }
    cudaEventRecord(stop);
    cudaEventSynchronize(stop);

    float ms;
    cudaEventElapsedTime(&ms, start, stop);
    ms /= repeat;

    // 计算 TFLOPS
    double flops = 2.0 * M * N * K;
    double tflops = flops / (ms * 1e9);

    printf("============================================\n");
    printf("GEMM Naive Kernel\n");
    printf("============================================\n");
    printf("矩阵大小: M=%d, N=%d, K=%d\n", M, N, K);
    printf("Block 大小: 16x16 = 256 threads\n");
    printf("Grid 大小: %dx%d blocks\n", grid.x, grid.y);
    printf("Kernel 耗时: %.3f ms\n", ms);
    printf("性能: %.2f TFLOPS\n", tflops);
    printf("============================================\n");

    // 验证正确性
    cudaMemcpy(h_C, d_C, bytes_C, cudaMemcpyDeviceToHost);
    printf("正在用 CPU 验证结果...\n");
    gemm_cpu(h_A, h_B, h_C_ref, M, N, K);

    if (verify(h_C, h_C_ref, M * N)) {
        printf("验证通过! GPU 结果与 CPU 参考一致\n");
    } else {
        printf("验证失败!\n");
    }

    // 清理
    free(h_A); free(h_B); free(h_C); free(h_C_ref);
    cudaFree(d_A); cudaFree(d_B); cudaFree(d_C);
    cudaEventDestroy(start); cudaEventDestroy(stop);

    return 0;
}
编译运行：
nvcc -O2 -o gemm_naive gemm_naive.cu && ./gemm_naive
预期输出：Kernel time ~1ms，Performance ~2 TFLOPS（A100 上），验证通过。

§8带走

  1. Naive GEMM：1 thread = 1 output element，内层 for 循环遍历 K 做内积
  2. 性能 ~1-5% of cuBLAS — 惨不忍睹，但代码正确、逻辑清晰
  3. 问题不是 coalescing（B 的访问其实是连续的），而是重复读取 — 每个 A/B 元素被独立读了 N/M 次
  4. 解药：Shared Memory — 让 block 内的 threads 协作加载、共享数据（下一节）
