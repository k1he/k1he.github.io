C2 · 内存层次 · Global / Shared / Register CUDA GEMM 系列 · 3/15

GPU 的内存系统是性能的关键。Global memory 慢但大，Shared memory 快但小，Register 最快但最小。GEMM 的优化本质就是"把数据从慢的地方搬到快的地方"。

§1内存层次金字塔

关键数字 (A100)

MemorySizeBandwidthLatencyScope
Register256KB/SM × 108 SM~20 TB/s~1 cycleThread
Shared164KB/SM~19 TB/s~20 cyclesBlock
L240 MB~5 TB/s~200 cyclesDevice
Global (HBM2e)80 GB2 TB/s~400 cyclesDevice
Register 到 Global 的带宽差距是 10x，延迟差距是 400x。GEMM 优化 = 尽量让数据在 Register/Shared 层复用。

§2Global Memory — HBM

// 分配
float* d_data;
cudaMalloc(&d_data, n * sizeof(float));

// kernel 内访问
float val = d_data[idx];  // 一次访问 ~400 cycles

Coalesced Access（合并访问）

  • 同一 warp 的 32 个 thread 如果访问连续 128 Bytes → 1 次内存事务
  • 如果地址不连续 → 多次事务 → 带宽浪费
// 好: coalesced (连续访问)
float val = A[row * N + threadIdx.x];  // thread 0→col 0, thread 1→col 1, ...

// 坏: strided (跨步访问)
float val = A[threadIdx.x * N + col];  // thread 0→row 0, thread 1→row N, ...

§3Shared Memory — Block 内的高速缓冲

__global__ void kernel() {
    __shared__ float smem[256];  // 声明: Block 内所有线程共享

    smem[threadIdx.x] = global_data[idx];  // 线程协作加载
    __syncthreads();  // 等所有线程都加载完

    // 现在可以读其他线程加载的数据
    float val = smem[threadIdx.x + 1];  // 快! ~20 cycles
}
  • __shared__ 关键字声明
  • Block 内所有线程可读写（需要同步）
  • __syncthreads() = barrier（确保所有线程到这里再继续）
  • 大小有限：48-164 KB/SM（用 cudaFuncSetAttribute 可调到 164KB on A100）

GEMM 中的用法

Global (HBM) → Shared Memory → Register → Compute → Register → Shared → Global
                    ↑                                              ↑
              tl.load 对应这里                              tl.store 对应这里

§4Bank Conflict — Shared Memory 的坑

  • Shared memory 分成 32 个 bank (0-31)
  • 每个 bank 宽 4 bytes
  • bank = (address / 4) % 32
  • 同一 warp 的 threads 如果访问同一 bank → bank conflict → 串行化
// 无 conflict: thread i 访问 smem[i] → 不同 bank
float val = smem[threadIdx.x];  // ✓

// 2-way conflict: thread i 访问 smem[2*i] → 偶数 bank 冲突
float val = smem[2 * threadIdx.x];  // ✗ 2-way bank conflict

// 解决: padding
__shared__ float smem[32][33];  // 33 instead of 32 → 错开 bank
Bank conflict 在 Triton 里你从来不需要担心——编译器自动处理。CUDA 里这是 shared memory 性能的头号杀手。

§5Register — 每个线程的私有存储

__global__ void kernel() {
    float acc = 0.0f;  // 在 register 里
    for (int k = 0; k < K; k++) {
        acc += a * b;   // register 级操作，最快
    }
    // acc 一直在 register，不碰内存
}
  • 每个线程最多使用 255 个 32-bit registers（编译器分配）
  • 用太多 register → "register spill" → 溢出到 local memory（实际是 global memory，很慢!）
  • GEMM 中 accumulator 占大量 register: BLOCK_M × BLOCK_N per thread
GEMM kernel 的 register 使用量通常是 128-255 个——已经接近上限。这限制了每个 SM 能运行的 block 数（occupancy）。

§6内存层次与 GEMM 的关系

GEMM 数据流

1. Global → Shared: 协作加载 A_tile[BLOCK_M, BLOCK_K] 和 B_tile[BLOCK_K, BLOCK_N]
   - 一个 block 的 threads 分工加载
   - __syncthreads()

2. Shared → Register: 每个线程从 shared 取自己需要的行列
   - thread (ty, tx) 取 A_shared[ty,:] 和 B_shared[:,tx]

3. Register: 计算 acc += a_reg * b_reg
   - 最快的操作

4. 写回: Register → Global
   - 直接写回（不经过 shared）
这就是为什么 Triton 的 tl.load 在 CUDA 里变成了两步：Global→Shared + Shared→Register。

§7cudaMemcpy — CPU ↔ GPU 数据传输

// H2D: Host → Device
cudaMemcpy(d_ptr, h_ptr, bytes, cudaMemcpyHostToDevice);

// D2H: Device → Host
cudaMemcpy(h_ptr, d_ptr, bytes, cudaMemcpyDeviceToHost);

// D2D: Device → Device
cudaMemcpy(d_dst, d_src, bytes, cudaMemcpyDeviceToDevice);
PCIe/NVLink 带宽: ~32-64 GB/s（PCIe 4.0 x16）。比 HBM 的 2 TB/s 慢 30-60x。所以要尽量减少 CPU↔GPU 传输。

§9带走

  1. 四层内存：Register (~0ns) > Shared (~20ns) > L2 (~200ns) > Global (~400ns)
  2. GEMM 优化 = Global→Shared→Register 的数据搬运编排
  3. Coalesced access: 同一 warp 访问连续地址 → 合并成一次事务
  4. Bank conflict: 32 个 bank，同一 bank 被多个 thread 同时访问 → 串行化
  5. Shared memory 需要 __syncthreads() 同步
