C13 · CUTLASS 源码解剖 · 工业级 GEMM 的架构 CUDA GEMM 系列 · 14/15

CUTLASS 是 NVIDIA 开源的高性能 GEMM 库。读懂它的架构，你就理解了所有 GEMM 优化的终极形态。这节不要求你能写 CUTLASS，但要能读懂。

§1CUTLASS 是什么

定位：

  • NVIDIA 开源的 C++ template 库
  • 目标：提供接近 cuBLAS 的性能 + 完全可定制
  • 版本演进：CUTLASS 2.x（传统）→ CUTLASS 3.x（CuTe-based, Hopper-first）
  • GitHub：github.com/NVIDIA/cutlass

典型使用场景

场景为什么用 CUTLASS 而非 cuBLAS
自定义数据类型FP8, INT4, NF4 — cuBLAS 不支持或支持有限
自定义 Epiloguebias + activation fusion — cuBLAS 的 epilogue 不够灵活
非标准 LayoutGrouped GEMM, Batched GEMM — 需要精细控制
极致性能调优可以手调 tile size、pipeline stages、swizzle 策略
cuBLAS 是黑盒，CUTLASS 是白盒。当你需要"改一点点"时，CUTLASS 是唯一选择。

四大组件

组件职责关键类
Iterator描述如何遍历 global memory tilesPredicatedTileIterator
MainloopK 循环：load → compute → advanceMmaPipelined
MMA矩阵乘累加（Tensor Core 指令）MmaTensorOp
Epilogue后处理：scale, bias, activation, storeLinearCombination
Mainloop 的核心逻辑：
for k = 0 to K/BK:
  ① 从 Global Memory 加载下一个 tile 到 Shared（异步 cp.async）
  ② 从 Shared 加载当前 tile 到 Register
  ③ 发射 Tensor Core MMA 指令
  ④ 同步 + advance iterator

§3CUTLASS 3.x 与 CuTe

CUTLASS 3.x 用 CuTe (Cute Tensor) 重写了底层抽象。CuTe 的哲学：用代数语言描述数据 layout 和操作映射，让编译器生成最优代码。

CuTe 四大概念

1. Layout — 描述数据排列（shape + stride）

auto layout = make_layout(make_shape(4, 8), make_stride(8, 1));  // 4×8 row-major

2. Tensor — Layout + pointer（逻辑视图）

auto tensor = make_tensor(ptr, layout);

3. TiledMMA — 描述一组 Tensor Core 操作的 tiling

auto mma = make_tiled_mma(SM80_16x8x16_F32F16F16F32{});

4. TiledCopy — 描述数据搬运（global↔shared↔register）

auto copy = make_tiled_copy(
    Copy_Atom<SM80_CP_ASYNC_CACHEALWAYS<uint128_t>, half>{}
);
CuTe 的学习曲线非常陡峭 — 大量 C++ template metaprogramming + 自定义代数系统。但一旦理解，你会发现它比 CUTLASS 2.x 的手动 iterator 更优雅、更不容易出 bug。

§4一个 CUTLASS GEMM 的使用示例

// 使用 CUTLASS 2.x device API
#include "cutlass/gemm/device/gemm.h"

using Gemm = cutlass::gemm::device::Gemm<
    cutlass::half_t,                     // Element A
    cutlass::layout::RowMajor,           // Layout A
    cutlass::half_t,                     // Element B
    cutlass::layout::RowMajor,           // Layout B
    cutlass::half_t,                     // Element C
    cutlass::layout::RowMajor,           // Layout C
    float,                               // Accumulator
    cutlass::arch::OpClassTensorOp,      // 使用 Tensor Cores
    cutlass::arch::Sm80,                 // A100
    cutlass::gemm::GemmShape<128,256,64>,    // Threadblock shape
    cutlass::gemm::GemmShape<64,64,64>,      // Warp shape
    cutlass::gemm::GemmShape<16,8,16>        // MMA shape (Tensor Core)
>;

Gemm gemm_op;
Gemm::Arguments args(
    {M, N, K},           // problem size
    {d_A, K},            // A + leading dimension
    {d_B, N},            // B + leading dimension
    {d_C, N},            // C (input) + leading dimension
    {d_C, N},            // D (output) + leading dimension
    {1.0f, 0.0f}        // alpha, beta
);

gemm_op(args);           // launch!
三级 Shape 嵌套：
ThreadblockShape<128,256,64> → 整个 threadblock 负责的 tile
WarpShape<64,64,64> → 每个 warp 负责的 sub-tile
MMAShape<16,8,16> → 单次 Tensor Core 指令的尺寸

从大到小嵌套，CUTLASS 自动算出 warp 数量和 register 分配。

§5CUTLASS Profiler

# 搜索最优 kernel 配置
./tools/profiler/cutlass_profiler \
    --operation=gemm \
    --m=4096 --n=4096 --k=4096 \
    --A=f16:row --B=f16:row --C=f16:row \
    --accum=f32 \
    --op_class=tensorop \
    --arch=sm_80

Profiler 的工作方式：

  • 枚举所有合法的 tile size / warp shape / pipeline stages 组合
  • 逐一编译 + 运行 + 测量性能
  • 输出最优配置及其 TFLOPS
  • 这就是 Triton @autotune 的 CUDA 版
实际工程中，先用 Profiler 找到最优 tile/warp/stages 组合，然后硬编码进你的 kernel 调用。

§7CUTLASS vs 手写 CUDA vs Triton

Triton手写 CUDACUTLASS
代码量~50 行~200-500 行~20 行（使用 API）
性能90-97% cuBLAS80-95%（看功力）95-100% cuBLAS
定制性中等最高高（template 参数）
学习曲线低高极高（C++ template）
新数据类型容易手动实现已有 FP8/INT4/NF4
Epilogue fusion手动手动内置（BiasAdd, GELU...）
选择建议：
• 快速原型 / 研究 → Triton
• 生产环境 + 需要定制 → CUTLASS
• 学习底层原理 → 手写 CUDA（就是我们这个系列在做的事）

§8带走

  1. CUTLASS = 模板化的高性能 GEMM，接近 cuBLAS 性能但完全开源可定制
  2. 三级分工：ThreadblockShape → WarpShape → MMAShape，从大到小嵌套
  3. CuTe (3.x)：Layout algebra 描述数据排列和操作映射，编译期生成最优代码
  4. Profiler 自动搜索最优配置（= Triton autotune 的 CUDA 原生版）
  5. 读源码路径：device → kernel → threadblock → warp → arch
你不需要"会写 CUTLASS"，但需要"能读懂 CUTLASS"。当你 debug 推理框架的 GEMM kernel 时，你会感谢今天的付出。
