C9 · Tensor Core 基础 · WMMA 与 MMA 指令 CUDA GEMM 系列 · 10/15

Tensor Core 是 GPU GEMM 性能的终极来源——一条指令完成 16×8×16 的矩阵乘。这节从硬件原理到 WMMA API，打通"为什么 tl.dot 这么快"。

§1为什么需要 Tensor Core

A100 GPU 性能对比

A100 GPU:
  FP32 CUDA Cores:  19.5 TFLOPS
  FP16 Tensor Cores: 312 TFLOPS  ← 16x faster!

Without TC: max ~19.5 TFLOPS (FP32) or ~39 TFLOPS (FP16 on CUDA cores)
With TC:   up to 312 TFLOPS (FP16 with FP32 accumulate)
不用 Tensor Core 的 GEMM，最多跑到理论峰值的 ~20%。用了 TC → 才能达到 80-100%。
这就是为什么 Triton 的 tl.dot 比 naive 的 a[:, None] * b[None, :] 快那么多——tl.dot 用了 Tensor Core。

§2Tensor Core 硬件原理

每个 Tensor Core 执行一个矩阵乘加（MMA）操作：

D = A × B + C
where A: [m, k],  B: [k, n],  C: [m, n]  →  D: [m, n]

各代 GPU 的 Tensor Core 指令

GPU指令Shape (m,n,k)输入类型累加类型
Volta (V100)hmma.168816×16×16FP16FP16/FP32
Ampere (A100)mma.m16n8k1616×8×16FP16/BF16/TF32/INT8FP32/INT32
Hopper (H100)mma + wgmma64×256×16FP16/FP8FP32
一条 mma 指令 = 2×16×8×16 = 4096 FLOPs。A100 每个 SM 有 4 个 TC → 每 cycle 做 4×4096 = 16384 FLOPs。

§3WMMA API (最高层抽象)

#include <mma.h>
using namespace nvcuda::wmma;

// Fragment 类型 (warp 级别的矩阵碎片)
fragment<matrix_a, 16, 16, 16, half, row_major> a_frag;
fragment<matrix_b, 16, 16, 16, half, col_major> b_frag;
fragment<accumulator, 16, 16, 16, float> c_frag;

// 初始化累加器
fill_fragment(c_frag, 0.0f);

// 加载 (从 shared/global memory 到 fragment)
load_matrix_sync(a_frag, A_ptr, lda);  // lda = leading dimension
load_matrix_sync(b_frag, B_ptr, ldb);

// 计算: D = A × B + C
mma_sync(c_frag, a_frag, b_frag, c_frag);

// 存储 (fragment 到 global/shared)
store_matrix_sync(C_ptr, c_frag, ldc, mem_row_major);

关键概念

概念说明
FragmentWarp 级别的矩阵碎片。一个 fragment 分布在 warp 的 32 个 threads 中
_sync 后缀整个 warp 同步执行（因为 fragment 跨 32 threads）
Shape (16, 16, 16)m=16, n=16, k=16 — 一次操作的矩阵维度
WMMA 是 warp 级 API——不是单个 thread 操作，而是 32 个 threads 协作完成一次 16×16×16 矩阵乘。

§4Fragment 的数据分布

Fragment 是分散存储在 32 个 threads 的 registers 中的。你不需要知道具体哪个 thread 存哪个元素——API 帮你管理。

fragment<matrix_a, 16, 16, 16, half, row_major> a_frag;
// a_frag 代表 16×16 = 256 个 half 元素
// 分散在 warp 的 32 个 threads 中
// 每个 thread 持有 256/32 = 8 个元素 (4 个 register)

§5WMMA 完整示例: 16×16 GEMM

#include <cuda_runtime.h>
#include <mma.h>
using namespace nvcuda::wmma;

#define WMMA_M 16
#define WMMA_N 16
#define WMMA_K 16

__global__ void wmma_gemm_16x16(
    const half* A, const half* B, float* C,
    int M, int N, int K
) {
    // 每个 warp 计算一个 16×16 的 C 块
    int warp_row = (blockIdx.y * blockDim.y + threadIdx.y) / 32 * WMMA_M;
    int warp_col = blockIdx.x * WMMA_N;

    fragment<matrix_a, WMMA_M, WMMA_N, WMMA_K, half, row_major> a_frag;
    fragment<matrix_b, WMMA_M, WMMA_N, WMMA_K, half, row_major> b_frag;
    fragment<accumulator, WMMA_M, WMMA_N, WMMA_K, float> acc_frag;

    fill_fragment(acc_frag, 0.0f);

    for (int k = 0; k < K; k += WMMA_K) {
        // Load A[warp_row:+16, k:k+16]
        load_matrix_sync(a_frag, A + warp_row * K + k, K);
        // Load B[k:k+16, warp_col:+16]
        load_matrix_sync(b_frag, B + k * N + warp_col, N);
        // Accumulate: acc = A × B + acc
        mma_sync(acc_frag, a_frag, b_frag, acc_frag);
    }

    // Store result
    store_matrix_sync(C + warp_row * N + warp_col, acc_frag, N, mem_row_major);
}
注意：这是 per-warp 的。一个 warp (32 threads) 一起调 mma_sync，产生 16×16 输出。

§6PTX MMA 指令 (底层)

// PTX assembly (Ampere m16n8k16):
mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32
    {%d0, %d1, %d2, %d3},      // D: 4 f32 registers
    {%a0, %a1, %a2, %a3},      // A: 4 f16x2 registers (8 halfs)
    {%b0, %b1},                 // B: 2 f16x2 registers (4 halfs)
    {%c0, %c1, %c2, %c3};      // C: 4 f32 registers
每个 thread 提供 A 的 8 个元素和 B 的 4 个元素，32 threads 一起凑出 16×8×16 的矩阵乘。

m16n8k16 每 Thread 的 Register 映射

操作数寄存器数数据量/thread32 threads 合计
A (matrix_a)4 × f16x28 个 half32×8 = 256 halfs = 16×16
B (matrix_b)2 × f16x24 个 half32×4 = 128 halfs = 16×8
C/D (accumulator)4 × f324 个 float32×4 = 128 floats = 16×8
注意：Ampere 的原生指令是 m16n8k16（不是 16×16×16）。WMMA 的 16×16×16 实际上是编译器用两条 m16n8k16 拼起来的。

§7Tensor Core 的限制

限制说明
Warp-level only单个 thread 无法独立使用 TC，必须整个 warp (32 threads) 协作
固定 shapem16n8k16 (Ampere)，不能自定义维度
输入类型限制FP16, BF16, TF32, INT8, FP8——不支持 FP32 输入
需要对齐内存地址 16-byte aligned
Layout 要求数据必须按特定 pattern 排列在 registers 中
WMMA API 帮你隐藏了 layout 细节。PTX mma 需要你手动管理。CUTLASS 提供了中间层 (CuTe) 来简化。

1Tensor Core: 一条指令做 16×8×16 matmul → 比 CUDA Cores 快 16x
