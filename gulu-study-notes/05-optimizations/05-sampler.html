PART 1先搞清楚 logits 是什么

模型 forward 的最后一步是 lm_head——一个 [hidden, vocab_size] 的大矩阵乘。它把 hidden state 投影到词表空间：

logits = lm_head(hidden_last)     # shape: [batch_size, vocab_size]
                                     # 例: [4, 151936] (Qwen3 词表 15 万)

logits[i, j] 不是概率，它是"未归一化的打分"——任意实数，可正可负可很大。要变成概率还要做 softmax：

probs = softmax(logits, dim=-1)    # [B, V]，每行加起来=1
next_token = argmax(probs, dim=-1) # [B]，取概率最大
关键认知：同样的 logits 可以采样出很多不同的 token。 这就是为啥同一个 prompt 用同一个模型，加了 temperature=0.8 每次输出不一样——采样引入了随机性。

PART 2Greedy · 最简单的采样

每次选概率最大的 token：

next_token = torch.argmax(logits, dim=-1)

特点：

  • 确定性：同一个 logits 每次输出一样
  • 不需要 softmax（argmax 对 logits 和 softmax 结果等价）
  • 容易循环：会倾向于重复高频 token（"The the the..."）

mini-sglang 的 SamplingParams.is_greedy：

# core.py:23
@property
def is_greedy(self) -> bool:
    return (self.temperature <= 0.0 or self.top_k == 1) and self.top_p == 1.0

只要 temperature=0 或 top_k=1，就算 greedy——完全跳过 softmax / flashinfer 采样，直接 argmax。速度最快。

PART 3Temperature · 调节随机性

给 logits 除以一个温度 T 再 softmax：

probs = softmax(logits / T, dim=-1)

T 的效果

T效果直觉
T → 0等价于 greedy最大值被放大到无穷，softmax 变 one-hot
T = 1原始 softmax模型的"天然"分布
T > 1更平均 / 更随机logits 差异被压缩，低概率 token 有更大机会
T → ∞均匀分布所有 logits 被除到趋于零，softmax 变 1/V

数学直觉

# 原始 logits: [5.0, 3.0, 1.0]
softmax([5, 3, 1])           = [0.867, 0.117, 0.016]     # 集中在第 0 个
softmax([5, 3, 1] / 0.5)     = [0.982, 0.018, 0.000]     # T=0.5 更集中
softmax([5, 3, 1] / 2.0)     = [0.705, 0.259, 0.036]     # T=2 更分散
softmax([5, 3, 1] / 10.0)    = [0.380, 0.340, 0.280]     # T=10 接近均匀
LLM 推理常用 0.7-1.0。聊天模式 0.7 比较稳；创作类 1.0 或更高。
T=0（greedy）适合确定性场景（代码生成、翻译）；T>1.2 风险是输出越来越随意失控。

PART 4Top-k · 截断尾部

只在概率最高的 k 个 token 里采样：

# 伪代码
top_k_vals, top_k_idx = probs.topk(k)
renorm_probs = top_k_vals / top_k_vals.sum()  # 归一化
next_token = top_k_idx[sample_from(renorm_probs)]

效果

  • top_k=1 = greedy
  • top_k=40（常用值）：保留前 40 个候选，筛掉尾部几万个没意义的词
  • top_k=-1 或 vocab_size：不截断，全部参与

Top-k 的问题

k 是固定的，但 "合理候选数" 是动态的。
有时模型输出非常确定（top 1 概率 99%，第 2 名 0.5%），k=40 会把 39 个垃圾候选也带进来增加噪声。有时输出模糊（top 10 概率都在 5-10%），k=40 反而切掉了合理候选。
→ 这就是发明 top-p 的动机。

PART 5Top-p · 动态截断

按概率累计截断：保留累计概率 ≥ p 的最少 token。

# 伪代码
sorted_probs, sorted_idx = probs.sort(descending=True)
cumsum = sorted_probs.cumsum(dim=-1)
# 找到第一个 cumsum >= p 的位置
mask = cumsum < p   # 之前的都保留
mask[first_above] = True  # 包含第一个超过的
filtered = sorted_probs * mask
next_token = sorted_idx[sample(filtered / filtered.sum())]

举例

probs = [0.6, 0.2, 0.1, 0.05, 0.03, 0.01, ...]
cumsum= [0.6, 0.8, 0.9, 0.95, 0.98, 0.99, ...]

p = 0.9 → 保留前 3 个（cumsum 0.9 刚好到第 3 个）
p = 0.95 → 保留前 4 个
p = 0.99 → 保留前 6 个
常用配置：temperature=0.7, top_p=0.9。既有随机性又不会太离谱。
top_k 和 top_p 可以同时用——先 top_k 截断，再 top_p 截断，最后在交集里采样。

PART 7mini-sglang 的 Sampler 实现

# engine/sample.py:48
@dataclass
class Sampler:
    device: torch.device
    vocab_size: int

    def prepare(self, batch) -> BatchSamplingArgs:
        params = [r.sampling_params for r in batch.reqs]
        if all(p.is_greedy for p in params):
            return BatchSamplingArgs(temperatures=None)   # ★ 全 greedy, 跳过 softmax

        MIN_P = MIN_T = 1e-6
        ts = [max(0.0 if p.is_greedy else p.temperature, MIN_T) for p in params]
        top_ks = [p.top_k if p.top_k >= 1 else self.vocab_size for p in params]
        top_ps = [min(max(p.top_p, MIN_P), 1.0) for p in params]

        temperatures = make_device_tensor(ts, torch.float32, self.device)
        top_k, top_p = None, None
        if any(k != self.vocab_size for k in top_ks):
            top_k = make_device_tensor(top_ks, torch.int32, self.device)
        if any(p < 1.0 for p in top_ps):
            top_p = make_device_tensor(top_ps, torch.float32, self.device)
        return BatchSamplingArgs(temperatures, top_k=top_k, top_p=top_p)

    def sample(self, logits, args) -> torch.Tensor:
        if args.temperatures is None:                     # greedy
            return torch.argmax(logits, dim=-1)
        return sample_impl(logits.float(), args.temperatures, args.top_k, args.top_p)

关键设计

① Batch 化 sampling params

每个请求的 temperature/top_k/top_p 可能都不同。prepare 把它们打成 batch 维的 GPU tensor（每行对应一个请求）。这样 kernel 可以并行处理不同请求的不同采样参数，不需要一个个循环。

② Fast path for greedy

如果 batch 里所有请求都是 greedy，直接 argmax——省掉 softmax + sampling kernel。这是很常见的优化，因为很多线上部署实际就是 greedy。

③ logits.float()

模型 forward 通常 bf16，但 sampling 前转 fp32。原因：softmax 的数值稳定性在 fp32 下更好，避免极端 logits 导致 overflow/underflow。这步 cast 成本很小（每 batch 只算一次）。

④ 跳过 top_k/top_p 若不必要

如果 batch 里所有请求 top_k == vocab_size（等于不截断），就不传 top_k tensor 给 kernel。同理 top_p=1 也跳过。省运算。

sample_impl 的多分支

# engine/sample.py:24
def sample_impl(logits, temperatures, top_k, top_p):
    import flashinfer.sampling as sampling

    probs = sampling.softmax(logits, temperatures, enable_pdl=is_sm90_supported())

    if top_k is None and top_p is None:
        return sampling.sampling_from_probs(probs)                      # 纯 temperature
    if top_p is None:
        return sampling.top_k_sampling_from_probs(probs, top_k)         # + top-k
    if top_k is None:
        return sampling.top_p_sampling_from_probs(probs, top_p)         # + top-p
    return sampling.top_k_top_p_sampling_from_probs(probs, top_k, top_p)  # 全用

FlashInfer 给这 4 种情况都提供了专门的 CUDA kernel，内部会选最优实现（例如 top_k=40 用 warp-level bitonic sort，top_k 更大时用 radix sort）。

PART 8Sampler 会被录进 CUDA Graph 吗？

会！看 engine/graph.py:139：

with get_global_ctx().forward_batch(batch):
    self.buffer.logits[:bs] = model.forward()
    with torch.cuda.graph(graph, pool=pool, stream=self.stream):
        self.buffer.logits[:bs] = model.forward()

等等，这里只录了 model.forward，没录 sampler.sample。再看 engine.py:202：

def forward_batch(self, batch, args):
    with self.ctx.forward_batch(batch):
        if self.graph_runner.can_use_cuda_graph(batch):
            logits = self.graph_runner.replay(batch)    # ← graph 产出 logits
        else:
            logits = self.model.forward()
    ...
    next_tokens_gpu = self.sampler.sample(logits[: batch.size], args)   # ← 在 graph 外
Sampler 是在 CUDA Graph 外面跑的！
  • 原因：采样参数 (temperatures, top_k, top_p) 每个 batch 都可能不同，无法固化到 graph 里
  • greedy 路径 (argmax) 非常快（一次 kernel），不录也没关系
  • flashinfer 的 sampling kernel 有自己的内部优化，不依赖 graph

那 sampler 的开销怎么办？

每次 decode 大概需要：

  • greedy 路径：~10 µs（一次 argmax kernel）
  • temperature + top_p：~50-100 µs（softmax + sort + sample）

相比 decode 本体 ~3-5 ms，采样占比 2-3%，不是瓶颈。而且 sampling kernel 本身是融合的，launch 只有 1-3 次。

总结

  • logits = 模型输出的"打分"，softmax 后才是概率
  • greedy：argmax，确定且最快
  • temperature：缩放 logits 调整随机性，T→0 退化为 greedy
  • top-k：固定数量的候选截断
  • top-p：按累计概率动态截断，更灵活
  • mini-sglang 用 flashinfer 的 fused sampling kernel，对 greedy 有 fast path
  • 采样不在 CUDA Graph 里（参数动态），但开销很小不影响整体
